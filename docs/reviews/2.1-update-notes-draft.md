- **Two findings from the 1.0.2 review, closed**:
  - The Low "automatic AI lookup without opt-in": a lookup now only runs when you click **Look up on the web…** in an agent's menu (`ai_popup.py`, through `plugin_ai.py`). Opening a page, a box or the map starts no lookup. Since 2.1.0, a lookup that fails also clears its "being looked up" mark.
  - Installer supply chain: every local LLM, and every program the plugin downloads and installs itself (Ollama, llama.cpp, KoboldCpp, Jan, mise, …), is one release named in `release_pins.py`: repository, tag, file, size and SHA-256. The download is checked against these before anything is unpacked or run (`install_ctl.Installer.install`, `open_verified`). Nothing comes from a release listing at run time. Agents installed or updated through their own tools are the exception: `mise use -g` / `mise upgrade` and `claude update` use those tools' own release channels, in a terminal you watch and only on Install/Update, as the README says.
- **Projects tab (AI Project Center: `project_center.py`, `project_supervisor.py`, `projects_page.py`, `projects_controller.py`, `project_detail_page.py`, `project_parts.py`)**: a board of your projects and a project page with Goal, Plan, Team, Activity and Setup. A team of your installed agents plans and runs the work in the project's folder, **only when you click** Draft plan / Approve / Run. Before every launch, Settings › Rules (`action_rules`) is checked. Agents run as argv lists, with the prompt on stdin or as one argument, under a supervisor that ends their whole process group (pidfd, start time checked). The store is `~/.config/omarchy/ai-agents-map/ai-project-center/`: 0700, an exclusive `flock`, atomic 0600 writes, and size caps on the store and on prompts.
  - Board: you drag a whole card to change the order, and separators show where it can go. There is no Move menu any more. Ctrl+↑/↓/Home/End still work. AI map: a box moves only inside its own card, onto a separator, and is never dropped into another card (`map_view.order_bar`).
  - In 2.1.0, `harnesses.NEWER_FACTS` includes `project`. The bundled agent add-ons were signed before the `[project]` table existed. With those add-ons switched on (which setup does), the Projects tab treated every agent as "not available". They now get the project commands from the plugin's own adapter for the same agent. An add-on that brings its own `[project]` table keeps it.
- **Scheduled project runs (2.1.0; new capability `service-management`, narrowly scoped)**:
  - `project_schedule.py`. `check()` accepts only the canonical schedule forms: daily, weekdays, weekly, every 1/2/3/4/6/8/12 hours, or monthly (day 1–31 or the last day), plus an optional end date. Keys and types must match exactly, and the schedule is stored in the project record. `on_calendar()` builds systemd's `OnCalendar=` from numbers and fixed day names only. `trigger()` runs an occurrence through the same `ProjectCenter.call("run", scheduled=True)` path as a manual Run, so the approval, Settings › Rules and the supervisor all apply. An occurrence that is skipped (the plan or team changed since approval, the run stopped, changes are waiting for review, the folder is busy) is recorded as a `schedule_note` event, and a desktop notification says why (`notify-send`, argv, plain text, 5 s). An occurrence that comes while the project is still running is only recorded, with no notification.
  - `schedule_units.py` → `sync()` / `remove_all()`. Only for a project you gave a schedule, it writes one timer and one service per project: `~/.config/systemd/user/ai-agents-map-schedule-<32 hex id>.{timer,service}`. Every file starts with the marker `# Managed by AI Agents Map`. A file of that name without the marker, or a link, is never replaced or removed (`_read_own` uses `O_NOFOLLOW`, checks the owner and caps the size). Files are written with `ai_core.atomic_write`. The unit folder is read one entry at a time and only names of ours are kept (2.1.3/2.1.4). After removing, `remove_all` reads the folder again: a unit of ours still there, or a folder that cannot be read, is a failure, so `clear` never exits 0 while a timer is left (2.1.4). `ExecStart=/usr/bin/python3 -I <plugin>/project_schedule.py run <id>`, and the plugin path must match `/[A-Za-z0-9._/+-]+`, otherwise no unit is written. No title, folder or other project data goes into a unit. The `systemctl --user` calls are limited to `daemon-reload`, `enable --now`, `restart`, `disable --now` and `show`, for these units only. Since 2.1.5 every sync makes the timers match the store, not only what changed: it writes what differs and asks systemd (`systemctl --user show`, 100 timers per call) about every other wanted timer; one it does not confirm as enabled, active and loaded (a failed or incomplete answer counts as not confirmed) is enabled and started again, so a start that failed once is retried by the next sync. If `disable --now` fails, the timer keeps its files and the failure is reported (`clear` names it and exits with 1); the next sync tries again (2.1.1/2.1.2). Each call is an argv list through `ai_core.read_bounded_output` (16 KiB cap, 30 s, own process group). Turning a schedule off, an end date that has passed, deleting the project, or `project_schedule.py clear` stops and removes the project's units. Since 2.1.6 `clear` refuses while another program (the app or a scheduled run) holds the project store, because that owner would put its timers back: it changes nothing, says so and exits with 1. Otherwise (since 2.1.5) it tries every step whatever failed before it (each schedule off, closing the store, removing every unit), names each failure and exits with 1 if any step failed or a unit is left. `ProjectCenter` calls `sync()` only when the app or the timer program passes the hook (`schedules=schedule_units.sync`). Without the hook, no unit is touched (tested).
  - `schedule_handover.py`: the hand-over queue and the lock. When a timer fires, `job()` writes a request (only the project id and a time) into a private folder: `$XDG_RUNTIME_DIR`, or, if that is missing or unsafe, the same per-user 0700 fallback under `/tmp` that the PID file uses (`pidfile.private_dir`). The folder must be 0700, owned by you, and is never followed through a link. Since 2.1.1, `_create()` writes a request or an answer to a new 0600 temporary file, checks every byte was written, and only then links it under its name. A reader never sees half a request. The queue folder is read one entry at a time, keeping at most 16 requests per pass, so memory stays bounded and other files cannot hide a request. The app's check on its main loop looks at no more than 1000 entries before it hands the work to a worker (2.1.2). The headless host keeps the store only while a real request or a working project is there (2.1.3). The owner of the project store claims the request with an atomic rename and runs it. The store's owner is whoever holds its exclusive `flock`: the app, or an earlier timer program. If nobody holds the store, the program opens it itself and waits under the supervisor until no project is working, then releases it. Since 2.1.5 it serves first and reconciles after: the timer's program opens the store without a timer sync (`ProjectCenter(sync_at_open=False)`), claims and runs its own occurrence, and only then lets the timers follow the store on a thread of its own while it keeps serving the queue; it lets the store go only after that. The app opens the store without that sync too and starts it on a thread right after opening, so serving a waiting request never waits for it. Slow `systemctl` calls therefore never make a waiting request stale. Since 2.1.6 only the store's owner syncs: `shutdown()` and `detach()` take the sync lock before they let the store go, so a sync that is going on ends first and none starts afterwards; an old owner's view can never undo a later owner's timers. Requests older than 3 minutes, malformed requests and requests for unknown ids are dropped, not run. No process is signalled. The app's PID file is read only to decide whether to wait 15 s for the app, and it is checked the way the toggle checks it: owner, `O_NOFOLLOW`, exe, script and start time.
- **Folder picker (`folder_picker.py`)**: the project folder dialog lists mounted disks and pinned folders. GTK bookmarks and favourites are read only from regular files: non-blocking `open`, size cap, no FIFO. At most 64 shortcuts are added, and broken bookmarks are skipped. One dialog is open at a time, and it closes with its window.
