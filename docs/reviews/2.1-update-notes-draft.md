Update notes for target commit `TARGET_SHA`:

Version 2.1.8 supersedes the pending 1.0.2 request (target `17c937f`). It brings the plugin to Maprisma 2.x (2.0.0 to 2.0.2). The map is unchanged as the plugin's main view. Changes since `17c937f`, grouped by feature:

- **Two findings from the 1.0.2 review, closed**:
  - The Low "automatic AI lookup without opt-in": a lookup now only runs when you click **Look up on the web…** in an agent's menu (`ai_popup.py`, through `plugin_ai.py`). Opening a page, a box or the map starts no lookup. Since 2.1.0, a lookup that fails also clears its "being looked up" mark.
  - Installer supply chain: every local LLM, and every program the plugin downloads and installs itself (Ollama, llama.cpp, KoboldCpp, Jan, mise, …), is one release named in `release_pins.py`: repository, tag, file, size and SHA-256. The download is checked against these before anything is unpacked or run (`install_ctl.Installer.install`, `open_verified`). Nothing comes from a release listing at run time. Agents installed or updated through their own tools are the exception: `mise use -g` / `mise upgrade` and `claude update` use those tools' own release channels, in a terminal you watch and only on Install/Update, as the README says.
- **Projects tab (AI Project Center: `project_center.py`, `project_supervisor.py`, `projects_page.py`, `projects_controller.py`, `project_detail_page.py`, `project_parts.py`)**: a board of your projects and a project page with Goal, Plan, Team, Activity and Setup. A team of your installed agents plans and runs the work in the project's folder, **only when you click** Draft plan / Approve / Run. Before every launch, Settings › Rules (`action_rules`) is checked. Agents run as argv lists, with the prompt on stdin or as one argument, under a supervisor that ends their whole process group (pidfd, start time checked). The store is `~/.config/omarchy/ai-agents-map/ai-project-center/`: 0700, an exclusive `flock`, atomic 0600 writes, and size caps on the store and on prompts.
  - Board: you drag a whole card to change the order, and separators show where it can go. There is no Move menu any more. Ctrl+↑/↓/Home/End still work. AI map: a box moves only inside its own card, onto a separator, and is never dropped into another card (`map_view.order_bar`).
  - In 2.1.0, `harnesses.NEWER_FACTS` includes `project`. The bundled agent add-ons were signed before the `[project]` table existed. With those add-ons switched on (which setup does), the Projects tab treated every agent as "not available". They now get the project commands from the plugin's own adapter for the same agent. An add-on that brings its own `[project]` table keeps it.
- **No scheduled runs in this version.** Versions 2.1.0 to 2.1.7 (2.1.0–2.1.4 pushed to GitHub, none submitted to the marketplace) also ran projects on a schedule with systemd user timers. A static Codex recheck found a Medium in that timer and hand-over plumbing in each of eight rounds, so this version leaves scheduling out entirely instead of patching it further: `project_schedule.py`, `schedule_units.py`, `schedule_handover.py` and their hooks in `project_center.py`, `projects_page.py`, `projects_controller.py`, `project_detail_page.py` and `project_texts.py` are removed (those files are as in 2.0.2, before scheduling). The plugin writes no timer, no `.service` file for projects and no queue. A project runs only when you click. The README tells anyone who installed 2.1.0–2.1.4 from GitHub how to remove timers left by them. A project store written by those versions still opens (an extra `schedule` field and `schedule_*` events are kept and ignored).
- **Folder picker (`folder_picker.py`)**: the project folder dialog lists mounted disks and pinned folders. GTK bookmarks and favourites are read only from regular files: non-blocking `open`, size cap, no FIFO. At most 64 shortcuts are added, and broken bookmarks are skipped. One dialog is open at a time, and it closes with its window.
- **Other 2.x features** (Maprisma parity), each started by a click:
  - Ask AI: your request goes to an agent you choose. Its JSON answer is checked against the real setup, and nothing runs from it directly.
  - Reports: an opt-in local activity log (owner-only files, 7 days by default) and Collect history from the agents' own session files. Credentials in topics are redacted (`activity_log`, `agent_activity_report`).
  - What is it doing?
  - Configure for this PC for local LLMs, with a preview, a backup and Undo (`provider_config.py`).
  - 3D map (`map_3d.py`).
  - Settings › Keyboard shortcuts (`settings_pages.SHORTCUTS`; a test checks every listed key against its handler).
  - The free GPU memory of a running local LLM is shown as a memory chip.
- **Docs**: README (Projects, Remove: leftover timers of 2.1.0–2.1.4) and `ARCHITECTURE.md`. The manual PDF is rebuilt (`assets/user-manual.pdf`). `preview.png` is new: real screenshots. Panel 1 is the map with the author's real setup. Panel 2 is part of the Projects board with demo projects written through `ProjectCenter` into a temporary config folder; nothing was planned or run. The manifest description is 459 characters.
- **Capabilities**: as in 1.0.2: `service-management` only for the provider watcher service and the LLM service start/stop, which are unchanged; `installer`, `package-manager` and `privilege` as before: system packages only in a terminal you watch, pinned and checksummed downloads. The update needs no manual setup beyond the standard install.
