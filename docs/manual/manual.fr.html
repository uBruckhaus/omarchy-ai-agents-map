À propos de ce manuel

Ce manuel décrit AI Agents Map, un plugin pour le bureau Omarchy : un bouton de la barre l’ouvre. Il utilise les couleurs du thème Omarchy (ou l’apparence Adwaita de GNOME) et garde ses réglages dans ~/.config/omarchy/ai-agents-map/.

Sommaire

Introduction

AI Agents Map montre la configuration IA de ton ordinateur sous forme de cartes et d'une carte : quels agents de programmation sont installés, quels modèles de langage ils utilisent — services cloud et moteurs locaux —, quels modèles ceux-ci servent et quels serveurs MCP et skills chaque agent possède. Et il te permet de modifier cette configuration en dessinant des lignes.

La fenêtre principale : la carte sur toute la largeur, au-dessus la carte GPU, dans l'en-tête le ! des problèmes ouverts.

Ce qu'il fait

  • Agents de programmation — Claude Code, Codex, GitHub Copilot, Cursor CLI, Gemini, OpenCode, Pi, Hermes et d'autres : leur version, leur abonnement, leurs limites et leur utilisation, et ce qui manque à chacun, avec la commande qui le corrige.
  • LLM locaux — llama.cpp, Ollama, LM Studio, vLLM, Jan, KoboldCpp et Strata : les installer, télécharger des modèles, régler la taille de contexte qui tient dans ta carte graphique et les démarrer avec les agents qui les utilisent.
  • Serveurs MCP et skills — trouvés sur ton ordinateur ou sur le web, avec des serveurs recommandés et une recherche dans le registre MCP officiel.
  • État des colonnes — un symbole sur la barre de chaque colonne, chaque problème avec le chemin vers l’endroit où le corriger ; ce à quoi ton installation peut servir figure sur la page d’accueil et dans l’Aide.

Notions clés

Agent
Un programme avec lequel tu parles et qui écrit du code ou fait des tâches, comme Claude Code.
Fournisseur de LLM
L'endroit où tourne le modèle d'un agent : un service cloud (Anthropic, OpenAI, …) ou un moteur de LLM local sur cet ordinateur (llama.cpp, Ollama, …).
Modèle
Le modèle de langage lui-même. Les modèles locaux sont des fichiers, le plus souvent au format GGUF.
Serveur MCP
Un petit programme ou service web qui donne des outils supplémentaires aux agents — lire des fichiers, chercher sur le web, piloter un navigateur. MCP est le Model Context Protocol.
Skill
Un dossier d'instructions (un SKILL.md) et parfois de scripts, qui apprend à un agent une tâche précise.

Rien ne change sans aperçu

Chaque modification des réglages d'un agent est d'abord montrée, ligne par ligne, avant que quoi que ce soit ne soit écrit. L'ancien fichier est gardé en sauvegarde, et la barre qui apparaît après la modification propose Annuler. L'app elle-même ne tourne jamais avec des droits d'administrateur ; seule l'installation d'un agent fourni comme paquet du système demande ton mot de passe, dans un terminal que tu vois.

Installation

Installer le plugin

Installez AI Agents Map depuis l’Omarchy Plugin Marketplace, ou dans un terminal :

omarchy plugin add https://github.com/uBruckhaus/omarchy-ai-agents-map.git --enable

Un bouton robot apparaît dans la barre. Tout le reste est fourni par une installation standard d’Omarchy, y compris ses add-ons signés. Pour exécuter des agents dans la fenêtre, installez VTE : sudo pacman -S vte4. Facultatif : mise installe et met à jour les agents.

Premier démarrage

Une nouvelle installation s’ouvre sur la page d’accueil : les agents et LLM locaux installés sur cet ordinateur sont des cartes déjà cochées, et Activer les place sur la carte (voir Configurer AI Agents Map). Après une mise à jour depuis une version antérieure du plugin, vos réglages restent, et les add-ons des agents et LLM locaux de cet ordinateur s’activent d’eux-mêmes : la carte montre ce qu’elle montrait avant.

Le bouton de la barre ouvre la fenêtre, la met au premier plan ou la masque si elle y est déjà. Fermer la fenêtre la masque ; le programme continue en arrière-plan et se rouvre donc aussitôt. Paramètres › Dans le lanceur ajoute une entrée au lanceur d’Omarchy.

Remarque Tant qu’un agent tourne dans la fenêtre, la fermeture demande d’abord : Arrêter et fermer (le LLM local de l’agent s’arrête alors aussi et libère la mémoire de la carte graphique) ou Laisser tourner.

Pendant que l’application regarde ce qui se trouve sur cet ordinateur à la première ouverture, un aperçu animé liste ce qu’elle trouve, type par type : agents, LLM locaux, serveurs MCP et skills, chacun avec un indicateur qui devient ✓ et un nombre, et combien ne sont pas encore connectés. Il disparaît de lui-même après un instant ; un clic le ferme tout de suite.

Supprimer le plugin

omarchy plugin remove ubruckhaus.ai-agents-map.

Avant la suppression, désactivez Paramètres › Démarrer les LLM locaux avec leurs agents pour que le surveillant en arrière-plan soit retiré aussi, et Paramètres › Dans le lanceur pour supprimer l’entrée du lanceur. Les changements faits avec l’application restent : réglages des agents, serveurs MCP, skills et LLM locaux installés. Désinstallez d’abord un LLM local (clic droit › Désinstaller…) si vous voulez qu’il disparaisse. Pour supprimer aussi l’état propre de l’application :

rm -rf ~/.config/omarchy/ai-agents-map ~/.local/state/ai-agents-map \
       ~/.cache/ai-agents-map ~/.local/share/ai-agents-map/addons

Configuration

La carte montre ce qui est configuré — les agents et LLM locaux installés, les serveurs MCP et dossiers de skills que les agents utilisent, et les modèles — et, estompés, les serveurs MCP et dossiers de skills trouvés sur cet ordinateur qu'aucun agent n'utilise encore, prêts à être connectés par une ligne (voir Trouvé sur ce PC). Tout le reste se fait dans Configuration (le bouton de l'en-tête, à côté de Carte), une carte par élément, dans des sections qui se replient d'un clic sur leur barre :

  • Comment les éléments arrivent sur ta carte — une carte repliée tout en haut ; ouvre-la pour cinq étapes numérotées : activer (ou trouver) ce que tu utilises, installer ce qui manque, te connecter à un agent en ligne, relier en dessinant, et ce qui apparaît tout seul.
  • Ce que tu peux en faire — ce à quoi sert la configuration (aide au quotidien, programmation, images, voix, recherche et écriture), une tuile chacun avec ce qui est là et l'étape suivante ; repliée, sa ligne dit combien sont prêts.
  • Agents IA, LLM locaux — tous ceux que l'app connaît. Une carte à bordure bleue est installée sur ce PC ; une grise ne l'est pas, et elle a Installer là où les installées ont Désinstaller. Un clic coche ou décoche la carte (✓), puis Appliquer active ou désactive son module. Désactiver la retire de la carte ; rien n'est supprimé. Tant qu'un agent tourne dans un terminal de AI Agents Map (celui de Demander à l’IA compris), son propre module ne peut pas être désactivé, mis à jour ni retiré ; tous les autres modules peuvent être modifiés. La page indique quel agent et propose Afficher le terminal.
  • Fournisseurs en ligne — le module des fournisseurs en ligne ; son menu propose Se connecter à … pour chaque agent installé qui les utilise.
  • Serveurs MCP, Skills, Modèles — une carte pour chaque élément installé. Un clic ouvre ses détails (pour un modèle, son menu). La carte + à la fin d'une section en ajoute un : Ajouter un serveur MCP, Ajouter des skills, Ajouter un modèle, Obtenir des extensions.
  • ⋯ ou un clic droit sur une carte ouvre le même menu que sa boîte sur la carte : mettre à jour, se connecter, démarrer ou arrêter, détails, désinstaller ou retirer, déplacer un modèle.
  • Un ↑ version jaune sur une carte signifie qu'une mise à jour est prête ; son menu propose Mettre à jour.
  • Un ! rouge sur une carte signale un problème ouvert à cet endroit ; survole-le pour savoir lequel.
  • Les détails d'un agent montrent Utilisation supplémentaire sous son forfait : si cela peut coûter de l'argent en plus au-delà des limites du forfait. Claude Code l'indique sur ton PC (avec la page pour le changer) ; pour les autres agents, l'app dit qu'elle ne le sait pas, vérifie alors auprès du fournisseur.
  • Une petite batterie sur la carte d'un agent en ligne montre ce qui reste de ses limites (une session, une semaine) : la plus serrée compte, jaune à un quart ou moins, rouge sous un dixième ; survole-la pour chaque limite et sa remise à zéro. Sur la carte d'un LLM local en marche, la batterie est la mémoire GPU encore libre, avec les mêmes couleurs ; survole-la pour voir combien ce LLM local en utilise.
  • Le symbole d'actualisation (F5) de la barre d'en-tête regarde à nouveau ce qui est installé, configuré et connecté, et refait les vérifications du démarrage (nouvelles apps, add-ons, mises à jour, problèmes ouverts).

Configuration : les agents installés ont un cadre bleu, ceux activés un ✓, les mises à jour un badge jaune et les problèmes un rouge ; le menu de Claude Code.

Serveurs MCP et skills, chaque section avec une carte pour en ajouter.

Il n'y a rien à masquer : ce que tu ne veux pas sur la carte se désactive ou se retire ici. Quand une installation ou une connexion tourne dans un terminal dans la fenêtre, Retour (ou × sur son onglet) ramène à la page d'où elle est partie.

Serveurs MCP locaux et Serveurs MCP en ligne (ceux joints par une adresse web) sont deux sections. Ajouter un dossier… dans Serveurs MCP locaux et dans Skills ajoute un dossier où l'application les cherche aussi — par exemple un disque partagé contenant des apps décompressées qui offrent un serveur MCP, ou un dossier de vos propres skills. Les dossiers ajoutés sont listés à côté du bouton ; ✕ sur l'un d'eux arrête d'y chercher (rien n'y est supprimé). Ce qui y est trouvé apparaît estompé sur la carte jusqu'à ce qu'une ligne le connecte : la Configuration n'a de cartes que pour ce qui est configuré.

Choisir ce que montre la carte

La carte montre tout ce qui est configuré. Les boutons de filtre Serveurs MCP, Agents, Fournisseurs et Modèles au-dessus de la carte (et Réglages › Carte) laissent de côté des colonnes entières et sont mémorisés.

Dans une petite fenêtre (jusqu'à 55 % de l'écran ou moins de 1150 pixels), la carte montre Agents et Fournisseurs ; dans une fenêtre moyenne (jusqu'à 80 % de l'écran ou moins de 1600 pixels), elle ajoute Modèles ; dans une fenêtre plus large, les quatre colonnes s'affichent. Une colonne que la vue laisse de côté s'active quand même avec son bouton au-dessus de la carte, et la carte se réorganise ; le filtre masque des colonnes dans chaque vue. Les colonnes affichées sont centrées et ajustent leur largeur (de 266 à 560 pixels) et leur espacement à l'espace libre, et la carte s'adapte à la largeur de la fenêtre jusqu'à ce que tu zoomes (Ctrl+0 l'adapte à nouveau).

Travailler avec la carte

Le modèle d’un agent forme une chaîne : une ligne de l’agent vers son fournisseur, une autre du fournisseur vers le modèle utilisé. Les modèles que personne n’utilise restent des cases sans ligne, et le filtre d’une carte (seulement ce qui est connecté ou épinglé) les masque. Tirer un fournisseur local vers l’un de ses modèles est une étape courte : le fournisseur utilise ce modèle, et un agent connecté ensuite à ce fournisseur le reçoit. Si un dépôt ne peut pas fonctionner, une courte note explique pourquoi, par exemple à quel fournisseur l’agent doit d’abord être connecté. Une connexion ou déconnexion simple demande Appliquer dans une petite fenêtre, puis une courte note le confirme, avec Annuler ; une erreur indique ce qui a échoué. Les changements nécessitant d’autres étapes utilisent l’aperçu détaillé. Quand un agent en appelle un autre, le chemin actif de l’agent appelé et la flèche entre eux prennent une couleur distincte, y compris pour les appels suivants. La flèche pointe vers l’agent utilisé ; une fois le travail terminé, elle reste atténuée. Le symbole en arbre sur la carte ouvre les sous-agents récents ; il est vif pendant leur travail et atténué quand seuls ceux terminés restent.

Demander à l’IA peut proposer les mêmes modifications de la carte, notamment changer un modèle existant, connecter un dossier de compétences, réparer une connexion défaillante et connecter ou déconnecter un agent. Le même aperçu demande confirmation avant application. Pour les questions de vitesse, mémoire graphique, contexte, Vulkan ou ROCm, elle ouvre Performances et s’appuie sur le matériel et les mesures de ce PC.

Sous la question, une carte défilante propose des exemples pour les serveurs MCP et les compétences, les agents, les fournisseurs et les modèles. En choisir un remplit la question avec sa catégorie au début (par exemple, Modèles:) et passe à cette catégorie sans rien envoyer. Vous pouvez modifier la question ou saisir vous-même une catégorie. Seul Demander l’envoie. La vue d’état permet toujours de consulter les constats de chaque catégorie.

Vous pouvez adapter ces exemples : le signet dans le champ de la question garde ce que vous avez tapé comme nouvel exemple de la catégorie choisie (jusqu’à 12 par catégorie), le crayon à côté d’un exemple le modifie sur place (Entrée le garde, Échap annule, un texte vide le supprime), son × le supprime et la flèche en fin de ligne rétablit les exemples intégrés.

  • Survolez une boîte pour la mettre en évidence avec tout ce qui y est relié : leurs bordures prennent la couleur d'accent. Rien ne s'estompe.
  • Cliquez sur une boîte pour la sélectionner ; Maj+clic en ajoute d'autres. Une boîte sélectionnée a une bordure plus marquée, tout ce qui y est relié reste en évidence, et les autres boîtes et lignes s'estompent. Un second clic sur elle, ou un clic sur une zone vide de la carte, termine la sélection. Pour masquer les lignes estompées, désactivez Réglages › Carte › Afficher les lignes estompées.
  • L'épingle en bas à droite d'une boîte garde la boîte et ses lignes en évidence, même quand autre chose est sélectionné.
  • Clic droit sur une boîte pour tout ce que propose sa carte dans Configuration : démarrer ou arrêter, détails, installer, se connecter, modèles, mettre à jour, retirer et plus.
  • ▶ dans la boîte d'un agent le démarre dans un terminal dans la fenêtre.
  • Les agents restent toujours au centre de la partie visible de la carte pendant le défilement.
  • Le chemin actif de chaque agent — agent → le fournisseur qu'il utilise → son modèle — est dessiné en gras. Pendant qu'un agent travaille, une lumière parcourt cette ligne.
  • L’encadré des statistiques d’utilisation : pendant qu’un agent travaille, de petits nombres sont écrits le long de sa ligne vers le fournisseur, dans la couleur de la ligne : la vitesse de sa dernière réponse (t/s, jetons par seconde), la taille de son contexte (1M) et la part utilisée (%, jaune à partir de 75 %, rouge au-delà de 90 %, comme les batteries). Ils viennent des propres fichiers de session de l’agent (nombres uniquement ; Claude Code, Codex et Pi). Ce qu’il affiche et sa taille de texte se règlent dans les Paramètres.
  • Une ligne rouge en pointillés relie un agent à un fournisseur pour lequel il est configuré mais qu'il n'utilise pas en ce moment (aucun de ses modèles en usage).
  • Quand des agents utilisent des modèles différents d'un même LLM local, les lignes vers ces modèles sont violettes : il les garde chargés en même temps, ou les alterne (voir Modèles en même temps).
  • La boîte d'un agent en ligne a la même batterie que sa carte dans Configuration : ce qui reste de ses limites ; la boîte d'un LLM local en marche, la mémoire GPU encore libre.
  • Un agent payé au token — connecté avec une clé d’API, donc sans limites de forfait pour une batterie — affiche à la place ce que coûtent aujourd’hui ses sessions actives aux prix de l’API, sous la forme d’un petit « 3,40 $ aujourd’hui » sur sa case et sa carte : vert, jaune à partir de 75 % de la limite du jour et rouge au-delà (Réglages › Coûts), mis à jour chaque minute. Ses détails montrent tout le coût d’API.
  • Quand un programme absent de la carte utilise un LLM local, la ligne de ce LLM vers son modèle devient épaisse et prend sa propre couleur (violet ou cyan, celle qui ressort le mieux des autres couleurs du thème), et une lumière la parcourt. Voir Utilisé par d'autres apps.
  • Quand un agent en a lancé un autre — Claude Code exécutant pi -p … ou codex exec … depuis son shell, par exemple —, une flèche longe la gauche de la carte des agents, de l’agent qui utilise l’autre vers celui qu’il utilise, et la lumière la parcourt ; son infobulle nomme les deux. Un agent peut en utiliser plusieurs à la fois, chacun avec sa propre flèche. Tant qu’il est utilisé, l’agent utilisé a aussi ses lignes vers son fournisseur et jusqu’à son modèle dans la couleur de la flèche, et la lumière y court dans cette couleur : tu vois d’un coup d’œil quel fournisseur et quel modèle travaillent pour qui.
  • Le symbole d'actualisation (F5) de la barre d'en-tête regarde à nouveau ce qui est installé, configuré et connecté, et refait les vérifications du démarrage (nouvelles apps, add-ons, mises à jour, problèmes ouverts).
  • Tant que la première ligne n'est pas tracée, une carte au-dessus de la carte montre comment en trois étapes ; Voir comment lance l'animation de l'Aide. Après la première connexion, ou avec ×, elle disparaît pour de bon.
  • Filtre les colonnes de la carte avec les boutons Serveurs MCP, Agents, Fournisseurs et Modèles au-dessus de la carte. La molette de la souris fait défiler la carte ; zoome avec les boutons − 100 % + et Adapter à la fenêtre en haut à droite ou Ctrl++ / − / 0.
  • Les boîtes sont dans une carte par catégorie (agents, fournisseurs en ligne, LLM locaux, une carte par dossier de modèles, serveurs MCP, skills). Fais glisser une carte par son en-tête pour changer l'ordre dans sa colonne, et une boîte dans sa carte pour changer l'ordre.
  • Clique sur l'en-tête d'une carte pour la replier jusqu'à son en-tête (▸ à droite de l'en-tête) et encore pour l'ouvrir (▾). Les lignes des boîtes d'une carte repliée s'arrêtent à son en-tête : tu vois toujours ce qui y est relié (les flèches entre agents sont masquées tant que la carte des agents est repliée). Ouvrir une carte déplace vers le bas les cartes situées en dessous dans sa colonne.
  • L'épingle à droite du zoom garde la disposition de la carte — l'ordre des cartes et des boîtes et les cartes repliées — après Actualiser (F5) et un redémarrage. Non épinglée, comme au départ, la carte revient à sa disposition par défaut à chaque actualisation et démarrage ; tes changements restent jusque-là. Disposition par défaut remet tout en place d'un coup.
  • Les cases estompées des cartes serveurs MCP et skills sont sur cet ordinateur, mais aucun agent ne les utilise. Tracez une ligne d'un agent vers l'une d'elles pour la connecter (voir Trouvé sur ce PC). Les serveurs MCP joints par une adresse web ont leur propre carte, Serveurs MCP en ligne, à côté de Serveurs MCP locaux ; les deux se replient comme toute autre carte.

Astuce La carte s'adapte à la largeur de la fenêtre jusqu'à ce que tu zoomes (Ctrl+0 l'adapte à nouveau). Jusqu'à 55 % de l'écran (moins de 1150 pixels), elle montre Agents et Fournisseurs ; jusqu'à 80 % (moins de 1600 pixels), elle ajoute Modèles ; au-delà, les quatre colonnes. Les boutons au-dessus de la carte activent n'importe quelle colonne dans n'importe quelle vue.

État des colonnes

La barre Demander à l’IA… de chaque colonne montre son état à gauche, et l’en-tête montre le pire état de toutes les colonnes, même d’une colonne masquée : une coche verte quand tout va bien, un triangle jaune pour les conseils, mises à jour ou suggestions, un ! rouge quand quelque chose est à corriger. Un clic sur le symbole ouvre la liste de la colonne, le plus grave d’abord : un agent non connecté, un LLM local sans modèles, une connexion qui ne fonctionne pas, peu d’espace pour les modèles, chacun avec un bouton vers l’endroit où le corriger. Demander à l’IA sur une ligne la place dans la demande ; seul Demander l’envoie. Un clic sur le symbole de l’en-tête mène à la première colonne concernée. La vérification ne fait que lire ; elle ne change, ne démarre et n’envoie rien.

La liste montre aussi les nouveaux programmes ou skills trouvés sur ce PC, ce qui est sur ce PC mais pas sur la carte, et les mises à jour des agents, LLM locaux et serveurs MCP installés, chacun avec son bouton. Les mises à jour sont vérifiées en arrière-plan à l’ouverture de la fenêtre, au plus toutes les six heures. Une mise à jour ne démarre que lorsque tu cliques sur Mettre à jour (voir Mises à jour trouvées). Ce à quoi ton installation peut servir figure sur la page d’accueil et dans l’Aide, sous Ce que vous pouvez en faire.

Cartes intelligentes sur la carte

Une barre repliée Demander à l’IA… se trouve en haut de chaque colonne de la carte, avec un symbole d’état à gauche : une coche verte quand tout va bien, un triangle jaune pour les conseils, mises à jour ou suggestions, ou un ! rouge quand quelque chose dans cette colonne doit être corrigé. La barre d’en-tête affiche l’état global des quatre colonnes (même masquées) et ouvre la première colonne concernée. Un clic sur le symbole d’état d’une colonne ouvre sa liste d’état : chaque point à corriger pour cette colonne avec le bouton qui ouvre l’endroit où il se corrige et Demander à l’IA pour préremplir la demande, les nouvelles versions des agents et LLM locaux installés (Mettre à jour lance mise upgrade ou le programme de mise à jour de l’agent dans un terminal, ou ouvre l’aperçu d’installation ; vérifié au plus toutes les six heures), les mises à jour de serveurs MCP des vérifications IA quotidiennes et Vérifier à nouveau. Sur la page d’accueil, Ce que vous pouvez en faire montre les cas d’usage (aide au quotidien, vibe coding, images, voix, recherche et écriture) comme Prêt, Presque ou Pas encore, avec ce qui existe pour chacun et la prochaine étape.

Au démarrage, l’application lit en arrière-plan le catalogue signé des modules : depuis son cache, et en ligne seulement si Chercher des modules en ligne est activé. La liste d’état de chaque colonne montre alors aussi les agents et LLM locaux de ce PC dont le module est désactivé ou pas encore installé (Obtenir des extensions ou Modules ouvre les modules à activer ou obtenir), les nouveaux programmes ou skills trouvés sur ce PC (Ajouter un serveur MCP…, Ajouter des skills…) et les modules installés ayant une version plus récente dans le catalogue. Tout mettre à jour les montre avec leurs versions et, après confirmation, les met à jour l’un après l’autre, chacun vérifié contre le catalogue ; un message dit ce qui a été mis à jour et ce qui ne l’a pas été.

Un clic sur la partie Demander à l’IA… de la barre ouvre la demande dans une fenêtre centrée au-dessus de la carte, avec l’assistant et son coût dans l’en-tête et les boutons dans le pied (ou propose Commencer lorsqu’aucun assistant IA n’est encore configuré). Avant tout envoi, la carte indique quel assistant répond (avec un menu si plusieurs sont prêts) et s’il tourne localement (Local, sans jetons) ou Utilise forfait/jetons ; seul un clic sur Demander envoie ta demande. L’assistant pose une question de clarification, propose de déplacer la demande vers la bonne colonne ou suggère des candidats vérifiés issus de vraies recherches. Dans la colonne Modèles, la carte affiche la VRAM, la RAM et l’espace libre de ce PC et marque chaque candidat comme Tient dans la VRAM, Utilise le délestage RAM ou Trop grand pour ce PC. Examiner ouvre l’aperçu de téléchargement avant que quoi que ce soit ne soit téléchargé ou modifié, et une fois le modèle prêt, tu peux facultativement le connecter à un agent via l’aperçu de connexion avec Annuler.

Dans la colonne Serveurs MCP et skills, l'assistant peut ajouter un serveur MCP du registre officiel, connecter un serveur à un agent ou le déconnecter. Il peut aussi déconnecter plusieurs serveurs ou tous en une seule étape, avec un seul aperçu et un seul Annuler. Tu choisis les agents, tu remplis ce dont le serveur a besoin (les clés restent sur ce PC et n'atteignent jamais l'assistant) et tu approuves la revue normale ; le changement est alors fait et la carte le montre. Il refuse tout le reste et indique la bonne colonne. Il peut aussi déconnecter des dossiers de skills dans la même étape. Il ne peut pas encore ajouter ni mettre à jour des skills, mettre à jour des programmes ni supprimer un serveur du PC.

Dans la colonne Modèles, l'assistant peut aussi retirer un modèle d'un LLM local : tu vois d'abord la revue normale, et les fichiers vont à la Corbeille quand c'est possible. Il peut aussi déplacer un dossier de modèles vers un autre disque, avec un aperçu et Annuler dans l’en-tête. Chaque dossier a sa propre revue. Il peut aussi déconnecter des agents d'un, de plusieurs ou de tous les modèles d'un LLM local, avec un seul aperçu et un seul Annuler ; aucun fichier n'est supprimé.

Dans la colonne Agents, l'assistant peut installer, mettre à jour ou retirer un agent, là où la page Agents le propose. Tu vois la revue normale ; l'étape s'exécute ensuite dans un terminal que tu peux suivre. Il ne démarre pas d'agents et ne change pas leurs réglages.

Dans la colonne Fournisseurs, l'assistant peut installer ou mettre à jour un LLM local, et le démarrer ou l'arrêter, là où l'app le propose ; la revue normale de l'app s'ouvre. Il ne peut pas désinstaller un fournisseur ni se connecter à un fournisseur en ligne.

Demander à l’IA propose aussi les autres étapes des menus de l’application, chacune par le même menu avec sa propre vérification et Annuler. Dans la colonne Agents : la question de test, la carte de la clé API (vous y tapez la clé ; l’assistant ne la voit jamais), les paramètres de sécurité, démarrer un agent ou arrêter un agent qui tourne hors de l’application, ses connexions et ses détails, et pour un module ses détails, l’activer ou le désactiver, l’installer, le mettre à jour ou le supprimer. Dans la colonne Fournisseurs : les mêmes étapes de modules pour les LLM locaux, et Rechercher une IA existante, qui cherche les programmes et dossiers de modèles déjà sur ce PC ; l’application ne désinstalle pas elle-même un programme de LLM local. Dans la colonne Modèles : charger, décharger ou importer un modèle, et le modèle qu’un LLM local utilise lui-même, vérifié par les mêmes règles qu’un changement de modèle et avec son propre Annuler, comme lorsque vous le tracez sur la carte. Dans la colonne Serveurs MCP et compétences : ce que montre Trouvés sur ce PC. Connecter un agent à un fournisseur en ligne le connecte à son propre fournisseur ; le fournisseur d’un autre agent est refusé avec la raison. Quand des agents quittent un LLM local, seule leur configuration change, comme lorsque vous retirez la ligne. Après un téléchargement, Demander à l’IA propose les agents qui peuvent utiliser un LLM local, et le modèle devient celui de cet agent, comme lorsque vous tracez la connexion.

Quand une colonne ne peut pas faire quelque chose mais que le web peut l'expliquer, un assistant en ligne cherche sur le web et la carte montre sa réponse avec ses sources ; un assistant local ne peut pas chercher sur le web et le dit. Après une telle réponse, Le faire avec … montre la consigne, puis l'agent travaille dans un terminal et demande avant chaque étape qui modifie des fichiers. La tâche elle-même attend dans un fichier privé du cache de AI Agents Map ; la ligne de commande de l’agent ne nomme que ce fichier, si bien que les autres comptes de ce PC ne peuvent pas la lire.

Démarrer et arrêter des agents

Les 50 derniers dossiers de projet sont conservés par agent.

Le sous-menu Démarrer de chaque agent comporte trois sections séparées par des lignes : Démarrer avec le dossier actuel, Choisir un dossier… et la liste déroulante avec recherche Projets récents. Cette liste défilante contient tous les dossiers utilisés pour démarrer cet agent depuis la carte, du plus récent au plus ancien. Sélectionnez un ancien projet, puis Démarrer. Le sélecteur de dossier démarre une session dans le dossier choisi. Aucun dossier épinglé n’est obligatoire : sans épingle, Démarrer utilise Paramètres › Dossier de démarrage des agents, ou votre dossier personnel. La page de détails affiche une carte défilante Projets récents avec tous les dossiers enregistrés. Cliquez sur une ligne pour ouvrir Démarrer avec ce dossier sélectionné. L’épingle définit le prochain dossier par défaut de cet agent ; un seul dossier peut être épinglé par agent. Le désépingler rétablit le défaut général. La corbeille retire l’entrée et son épingle de l’historique de cet agent, jamais le dossier ni ses fichiers. Le même sous-menu, historique et épingles s’appliquent à Démarrer ici et Démarrer dans un terminal. Redémarrer rouvre le sous-menu. Les sessions actives conservent leur dossier ; les choix annulés et les démarrages échoués n’ajoutent aucun historique.

  • ▶ dans la boîte de l'agent ou Lancer ici dans son menu démarre l'agent dans un terminal dans la fenêtre, à la place de la carte. Cela nécessite VTE (vte4).
  • Lancer dans un terminal l'ouvre dans sa propre fenêtre de terminal.
  • Pendant qu'il tourne dans la fenêtre : Afficher le terminal et Arrêter. Arrêter met fin à l'agent et à tout ce qu'il a démarré, comme ses serveurs MCP.
  • Terminaux… liste où d'autre l'agent tourne : Ici, dans cette fenêtre, chaque Fenêtre de terminal (un clic la met au premier plan) et chaque instance En arrière-plan — une sans fenêtre, comme claude -p … lancé par un script ou par un autre agent. L'onglet se termine quand l'instance se termine. C'est le seul endroit où l'app montre du texte de conversation, et seulement pour l'instance sur laquelle tu cliques.
  • Arrêter… — aussi le petit bouton d'arrêt à gauche de ▶ dans la boîte de l'agent — arrête une de ses instances en dehors de cette fenêtre. Choisis-la dans la liste, qui indique où et quand chacune a été lancée. Elle est priée de se terminer (SIGTERM) et, si elle est encore là au bout de 3 secondes, terminée. Quand des agents ont des terminaux dans la fenêtre, une rangée d'onglets au-dessus de la carte montre un onglet par terminal, avec un point pour travaille, tourne ou terminé. Un clic sur un onglet affiche ce terminal ; × ferme un terminal terminé.

Un agent ouvert n'importe où sur l'ordinateur reçoit un point vert et tourne, et la boîte du modèle avec lequel il tourne indique utilisé · <agent>.

Trafic réseau

La boîte et la carte d'un agent en cours montrent ce qu'il reçoit et envoie (↓ entrant, ↑ sortant). Clique sur cette ligne, ou sur ⇅ dans l'en-tête pour tous les agents en cours, pour ouvrir sa page réseau : Maintenant, Les 5 dernières minutes en graphique (entrant en vert, sortant en bleu), Où ça va — API en ligne, LLM locaux, ce PC et ton réseau local, chacun avec sa part — et Programmes : l'agent lui-même et les programmes qu'il a lancés, comme ses serveurs MCP. Sous-agents

Claude Code et OpenCode peuvent confier des parties d’une tâche à des sous-agents. Tant qu’un des sous-agents d’un agent travaille, sa case sur la carte montre une petite marque en arbre à côté de ⇅ ; s’il n’en a que de terminés dans la liste, la marque est atténuée. Cliquez dessus pour ouvrir la page Sous-agents de l’agent : une carte à elle, disposée comme la grande, avec la carte de l’agent à gauche et une carte Sous-agents à droite. Chaque case montre la tâche du sous-agent, son type, le dossier où travaille sa session, et au travail ou terminé il y a … minutes. La lumière parcourt les lignes vers ceux qui travaillent ; ceux qui ont fini sont atténués. Survolez une case pour lire toute sa tâche.

Les sous-agents d’un agent : deux au travail, un terminé.

Combien de temps les sous-agents terminés restent dans la liste (30 minutes) et combien au plus (10) se règle dans Réglages › Sous-agents ; ceux qui travaillent sont toujours affichés. La page ne lit que le type de chaque sous-agent et la description d’une ligne de sa tâche, dans les fichiers de l’agent lui-même (les dossiers de session de Claude Code, la base de données d’OpenCode), jamais ce que disent les sous-agents.

Des agents qui travaillent ensemble

Un agent qui en a lancé un autre et l’utilise — Claude Code qui exécute pi -p … par son shell, par exemple — lui est relié sur la carte par une ligne courbée le long de la droite des cases des agents. La lumière y circule tant que l’un des deux travaille. Cela se déduit uniquement de l’arbre des processus (les processus des agents et leurs parents), et la ligne est affichée, jamais modifiée. Les sous-agents de Claude Code, Codex, GitHub Copilot, OpenCode et Goose sont lus comme dans l’app.

Coûts

Les détails d’un agent montrent ce que coûtent ses jetons aux prix d’API des fournisseurs : aujourd’hui, sur les 7 et 30 derniers jours, et par modèle réparti en entrée, sortie, lecture du cache et écriture du cache. Coût d’API pour un agent payé au jeton (avec la part de la limite par jour), Valeur API pour un agent avec abonnement (qui la couvre). C’est une estimation tirée des nombres de ses propres fichiers de session ; aucun texte n’en est lu. Réglages › Coûts fixe la Devise (en euros au taux de référence quotidien de la Banque centrale européenne, récupéré une fois par jour), la Limite par jour et les niveaux Jaune à partir de et Rouge à partir de (rouge toujours au-dessus du jaune). Les fichiers de session de Claude Code sont lus à partir de là où le dernier coup d’œil s’est arrêté, si bien que les très longues sessions comptent en entier ; le premier coup d’œil sur un PC qui en a beaucoup peut en demander deux pour être complet.

Sur la carte, un agent avec des limites de forfait affiche dans sa case une petite batterie avec ce qui reste de la limite la plus serrée, et un agent payé au jeton y affiche le coût du jour, avec à côté une batterie de ce qui reste de la limite par jour ; vert, jaune ou rouge selon les niveaux de Réglages › Coûts, les détails dans son info-bulle. Les deux sont regardés de nouveau chaque minute. Une batterie dont les chiffres ne sont peut-être plus à jour (le collecteur les a gardés après une interrogation échouée, ou ils ont été mesurés il y a plus de 30 minutes) est estompée, et son info-bulle dit quand ils ont été mesurés ; une limite sans heure de remise à zéro n’est alors plus affichée. Les limites viennent du collecteur d’utilisation d’Omarchy pour cet agent (omarchy-agent-usage-claude, -codex, …) : sur Omarchy par Omarchy lui-même, sur un autre bureau quand le collecteur est dans ton PATH. Sans collecteur, Codex est interrogé lui-même tant qu’il est connecté : son propre codex app-server donne les limites de son forfait (aucun prompt n’est envoyé, et il est refermé aussitôt). Seul le Codex installé est interrogé, jamais un lanceur qui l’installerait ou le mettrait à jour d’abord ; une connexion dans le trousseau ou dans le dossier que nomme CODEX_HOME compte aussi. Tant que l’application est ouverte, les limites sont redemandées toutes les dix minutes ; après une déconnexion, elles ne sont plus affichées. AI Agents Map ne lit lui-même aucun fichier de connexion ; c’est le collecteur ou l’agent qui le fait. Un agent dont les propres données de sessions disent ce qu’elles ont coûté (Hermes, OpenCode) compte comme payé au jeton ; un coût seulement estimé ne compte pas. Avec Avertir au rouge activé, un coût dans le rouge reçoit une notification de bureau par jour.

Clic droit sur un agent ou un LLM local › Configurer… ouvre sa propre configuration dans un onglet de terminal de la fenêtre, pour ce que l'app ne règle pas elle-même — par exemple hermes setup ou le menu d'Ollama ; LM Studio ouvre sa fenêtre. Se connecter

Se connecter… dans le menu d'un agent (dans Configuration ou sur la carte) montre ce dont l'agent a besoin et ses propres façons de se connecter :

  • Un abonnement ou un compte — la connexion propre à l'agent tourne dans un terminal dans la fenêtre (par exemple claude auth login ou codex login). Ton mot de passe ou la connexion dans le navigateur restent entre toi et l'agent ; l'app ne les voit jamais. Quand l'agent le demande, le terminal dit quoi taper (Pi et Copilot : /login).
  • Une clé API — pour les agents qui en lisent une : la clé va dans un champ mot de passe, puis directement dans la propre commande de l'agent (Codex la stocke lui-même) ou dans le fichier que lit l'agent (Gemini : ~/.gemini/.env, lisible par toi seul). Elle n'atterrit jamais dans une ligne de commande, un journal ou les réglages de l'app, et l'app ne la garde pas. La facturation API de Claude Code est sa propre connexion à l'Anthropic Console, donc aucune clé ne passe par l'app.

Se connecter à Claude Code : un abonnement ou la facturation API, tous deux avec la connexion propre à Claude Code.

Ensuite, la carte montre le fournisseur en ligne de l'agent et ses modèles.

Clés d’API

Un agent qui lit une clé d’API affiche Clé API… dans ses détails. La carte indique où va la clé avant que tu la tapes : à la commande propre de l’agent (Codex : codex login --with-api-key) ou dans le fichier que l’agent lit (Gemini : ~/.gemini/.env, écrit comme un nouveau fichier lisible par toi seul ; ses autres lignes restent). Le champ masque ce que tu tapes, et Enregistrer ne devient disponible que pour quelque chose qui ressemble à une clé. La clé va à un processus de travail séparé par son entrée standard ; elle n’entre jamais dans une ligne de commande, un journal, une sauvegarde ni les réglages de l’application, et l’application ne la conserve pas. Quand la commande propre de l’agent répond, sa dernière ligne s’affiche, sans la clé.

Mettre à jour lance la mise à jour de la façon dont l'agent a été installé — par exemple mise upgrade <outil> ou claude update — dans sa propre fenêtre de terminal pour que tu puisses la suivre.

Nouveaux agents

Quand un agent que l'app ne connaît pas encore apparaît, elle demande une fois à un agent installé (Claude Code, sinon Codex) de chercher sur le web où cet agent range ses skills et ses serveurs MCP. LLM locaux

Un moteur de LLM local fait tourner des modèles de langage sur ta propre carte graphique, si bien que les requêtes ne quittent jamais l'ordinateur. L'app les installe, les démarre et les arrête pour toi.

Installer un LLM local

Clic droit sur un LLM local gris (non installé) de la carte › Installer…. Tu choisis le dossier du programme, le dossier des modèles (celui de tes autres LLM locaux est proposé) et s'il démarre à l'ouverture de session. Il est installé pour ton utilisateur seulement, avec un service utilisateur, donc aucun mot de passe n'est nécessaire. Chaque téléchargement doit correspondre à la somme SHA-256 publiée par sa version avant d'être décompressé ou exécuté.

Son moteur et ses modèles viennent ensuite, dans les écrans de Strata (voir Strata). AI Agents Map ne propose pas de Désinstaller… pour lui ; comment le supprimer figure aussi dans cette section.

Installé ainsi, un LLM local propose aussi Mettre à jour… (la version précédente est gardée en secours), Dossier des modèles… et Désinstaller…, qui retire le programme, la commande, le service et les réglages, mais jamais les modèles. Les LLM locaux que tu as installés toi-même sont affichés, mais jamais modifiés.

Un LLM local pas encore installé affiche Installer dans Fournisseurs et modèles, et le guide du premier agent propose Installer mise, Installer Node.js et Installer pour le LLM local dont son parcours a besoin. AI Agents Map cherche d’abord la dernière version et l’affiche sur une carte : ses fichiers et leur taille, le dossier du programme (~/.local/share/ai-agents-map/<nom>, un dossier par version), le dossier des modèles qu’il contient et ta carte graphique. Pour llama.cpp et KoboldCpp, choisis-y la variante (Vulkan, ROCm, CUDA ou CPU) ; une autre variante est recherchée à nouveau avant toute installation. Un LLM local avec un service utilisateur propose aussi Démarrer maintenant et Démarrer à la connexion.

Installer télécharge les fichiers, vérifie chacun avec la somme de contrôle indiquée par sa version et les décompresse ; rien du téléchargement n’est exécuté pendant l’installation (l’AppImage de Jan se décompresse lui-même dans un bac à sable isolé). Strata est l’exception : son propre install.sh, vérifié avec la somme de contrôle de sa version, s’exécute et l’installe dans votre dossier personnel. Un programme déjà installé autrement, ou un fichier de réglages ou un service qui existe déjà, n’est jamais remplacé : la carte le refuse. Ollama, llama.cpp, KoboldCpp, Jan, Strata et mise s’installent ainsi ; LM Studio et vLLM non, car aucune version avec somme de contrôle n’existe pour eux.

Chaque étape lancée depuis le guide du premier agent — installer, se connecter, la question de test, Fournisseurs et modèles, Connexions — te ramène au guide avec Retour, actualisé, pour que l’étape qui vient d’être faite apparaisse comme faite.

Démarrer et arrêter avec les agents

Connecte une fois un agent à un LLM local, puis démarre simplement l'agent — même app fermée ou après un redémarrage. Son LLM local démarre avec lui, et quand le dernier agent qui l'utilise se termine, le LLM s'arrête environ cinq secondes plus tard, ce qui libère à nouveau sa mémoire graphique.

Un petit service d'arrière-plan s'en charge, ai-agents-map-providers.service. Il est mis en place avec la première connexion à un LLM local et retiré quand la dernière disparaît ou quand tu désactives Réglages › Démarrer les LLM locaux avec leurs agents.

Remarque KoboldCpp met quelques secondes à démarrer, plus longtemps que certains agents n'attendent. Il démarre donc à l'ouverture de session, et quand le dernier agent se termine, seul son modèle est déchargé.

Remarque Strata ne démarre pas avec ses agents. Démarre-le sur la carte (le bouton ▶ de sa boîte) ou dans Strata lui-même avant de travailler avec un agent qui y est connecté.

Strata

Strata est un moteur d'inférence local avec sa propre application de terminal. Il sert un modèle à la fois sur 127.0.0.1:8080 et parle les API d'OpenAI et d'Anthropic, de sorte que les agents s'y connectent comme aux autres LLM locaux. AI Agents Map le trouve par sa propre commande strata (un autre programme de ce nom, comme le gestionnaire de fichiers Strata dans /usr/bin, n'est pas pris pour lui), par son serveur en marche et par ses modèles : les configurations d'exécution que Strata garde dans ~/.local/share/strata/install.

Choisir, télécharger et régler un modèle se fait dans les écrans de Strata : lance ~/.local/bin/strata launch dans un terminal (~/.local/bin/strata launch --status montre ce qui est servi). Une fois que Strata a démarré un modèle ainsi, il le retient comme préréglage de lancement. Dès lors, Démarrer sur la carte (le bouton ▶ de la boîte de Strata) démarre le dernier préréglage utilisé (strata launch --preset … --no-tui, qui rend la main quand le modèle est servi ; les gros modèles prennent quelques minutes), et Arrêter l'arrête (strata launch --stop).

Strata et llama.cpp utilisent tous deux le port 8080, sauf réglage contraire. Un agent connecté depuis la carte nomme son LLM local (strata-local) : il reste donc à Strata même quand llama.cpp utilise aussi ce port ; un seul des deux peut servir sur un port à la fois.

AI Agents Map ne supprime pas Strata. Pour le supprimer toi-même, efface son terminal (~/.local/share/strata/terminal) et le lien ~/.local/bin/strata. Ses moteurs et configurations d'exécution sont dans ~/.local/share/strata (components, install), ses modèles dans les dossiers choisis dans Strata, et les conversations de l'application de bureau dans ~/.strata ; efface-les seulement si tu n'en veux plus.

Les détails d'un LLM local

Clique sur la carte d'un LLM local dans Configuration, ou clic droit sur sa boîte de la carte › Détails. Sous les tuiles (modèles, agents, adresse) viennent les mêmes cartes repliables que pour les agents : Utilisation et jetons — ce que tes agents ont envoyé par lui ces derniers jours, par agent et par modèle, d'après les propres chiffres de session des agents et associé par nom de modèle —, puis État, Gestion des risques, Ce que veulent dire les mots et Configuration.

Performances

Un LLM local dont l'app connaît les réglages (llama.cpp, Ollama installé par l'app) a une carte Performances sur sa page de détails :

  • Variante, Piles GPU et Mémoire vidéo : ce qui le fait tourner — ROCm, Vulkan, CUDA ou le CPU (pour llama.cpp, lu dans sa propre liste de périphériques, aussi pour une version que tu as compilée toi-même), lesquelles de ces piles ce PC possède, et la mémoire de la carte.
  • Contexte par modèle : la taille du fichier de chaque modèle, le contexte réglé actuellement, le contexte que la carte peut lui accorder — son fichier plus le cache du contexte, lu dans l'en-tête du modèle — et celui pour lequel il a été entraîné. ! marque un contexte plus grand que ce que la carte peut contenir (le modèle ne se chargerait pas, ou déborderait en RAM), ↑ un contexte que la carte pourrait agrandir ; Régler sur … le change.
  • Demander à … : l'assistant local (ou l'agent en ligne) examine ces faits — seulement des noms et des nombres — et propose des changements : des réglages comme flash attention, le type de cache du contexte, les couches GPU, les requêtes parallèles et la taille des lots ; des contextes ; une autre variante quand elle aiderait clairement. L'app ne garde que les suggestions qu'elle peut assumer (un réglage connu avec une valeur autorisée, un contexte que la carte peut contenir) et montre chacune avec sa raison. Appliquer l'écrit avec une sauvegarde ; le message propose Annuler, ou Redémarrer maintenant quand elle ne compte qu'après un redémarrage. Une autre variante est seulement suggérée : installe-la depuis le menu du LLM local.

Pour Ollama, ses réglages valent pour tous les modèles à la fois (le fichier d'environnement de son serveur).

Un LLM local dont l’app peut régler les paramètres (llama.cpp, Ollama) a Performances dans Fournisseurs et modèles. Il montre la build sous laquelle il tourne, les piles GPU de ce PC et la mémoire vidéo, puis Contexte par modèle : la taille de chaque modèle, son contexte actuel, ce que la carte tient pour lui et ce pour quoi il a été entraîné. Un modèle avec plus de contexte que la carte n’en tient est signalé, de même qu’un modèle pour lequel la carte a encore de la place ; pour llama.cpp, Régler sur … le règle. Réglages pour tous les modèles liste les réglages du moteur avec leur effet ; un réglage avec une liste de valeurs peut s’y changer. Chaque changement est montré d’abord et écrit avec une sauvegarde, si bien qu’Annuler le remet ; il compte après un redémarrage du LLM local. Sous Conseils d'un agent, Demander à … fait examiner ces faits par l’agent des vérifications IA (noms et nombres seulement, par le web uniquement) : il propose des réglages, des contextes, une autre build ou des remarques, chacun avec sa raison. L’app ne garde que ce qu’elle peut assumer — une valeur permise, un contexte que la carte tient, une build que le LLM local possède — et Appliquer passe par le même aperçu. Les jetons sont ceux de l’agent ; l’exécution figure dans le Smart Check. Pour llama.cpp, l’app mesure aussi chaque modèle sur cette carte avec la version qu’utilise son service (ROCm ou Vulkan) : après un téléchargement, quand la version change, et avec Mesurer et régler. Elle essaie plusieurs tailles de lot, garde la plus rapide et donne au modèle le plus grand contexte que laisse la mémoire vidéo mesurée, avec un cache q8_0 et flash attention sauf si vous avez choisi autrement ; les agents reliés à llama.cpp reçoivent aussi le nouveau contexte. Elle attend tant qu’un modèle est chargé, et Annuler rétablit les anciens réglages.

Mémoire GPU et libérer la mémoire GPU

Dans la carte GPU au-dessus de la carte, Mémoire GPU montre combien est utilisé, réparti entre LLM locaux, bureau et applications, et libre ; Activité GPU montre la charge, la température et la puissance. La boîte de chaque LLM local montre combien de mémoire il occupe, et les modèles chargés reçoivent un point vert.

Clic droit sur un LLM local pour Démarrer, Arrêter, le démarrage à l'ouverture de session et Libérer la mémoire GPU : ses modèles sont déchargés, il continue de tourner et en recharge un quand on le lui demande.

Quand le dernier agent qui utilisait un LLM local se ferme et que le LLM occupe encore ses modèles, un message demande s'il faut rendre la mémoire : La libérer les décharge, Garder les laisse chargés.

Un LLM local qui occupe de la mémoire GPU reçoit un bouton d'arrêt rouge sur sa case. Il demande d'abord : Libérer la mémoire GPU décharge ses modèles ; Arrêter l'arrête. Pour LM Studio, le bouton est Arrêter le serveur : seul son serveur s'arrête, l'application reste ouverte avec ses modèles chargés. Un modèle chargé par un LLM local mais utilisé par aucun agent lui est relié par une ligne claire continue.

LM Studio peut être ouvert sans son serveur. Sa case affiche alors serveur arrêté avec un point jaune, les agents ne peuvent pas l'atteindre et son menu propose Démarrer le serveur (lms server start).

Modèles en même temps

llama.cpp, LM Studio et Ollama peuvent garder plusieurs modèles chargés. Quand tu connectes des agents à des modèles différents d'un même LLM local, l'app règle combien il en garde chargés en même temps sur le nombre qu'utilisent ses agents — avec le même aperçu, la même sauvegarde et la même Annulation que la connexion — et propose de le redémarrer s'il tourne, car il lit ce nombre au démarrage. Là où ce nombre ne relève pas de l'app (une installation système, ou ta propre commande de démarrage), une note dit où le régler.

Quand les modèles ensemble ne tiennent pas dans la mémoire du GPU, un avertissement le dit : le LLM local les alterne alors, ce qui est lent, ou une partie d'un modèle tourne sur le processeur. Le démarrage d'un agent vérifie la même chose : si charger son modèle demande plus de mémoire GPU qu'il n'en reste, on te le demande d'abord, avec ce qui occupe la mémoire en ce moment — Libérer la mémoire GPU, puis démarrer, Démarrer quand même ou Annuler.

Après l’application d’un changement du LLM local ou du modèle d’un agent, l’app regarde combien de modèles différents les agents de chaque LLM local utilisent désormais. Là où elle peut fixer ce nombre — les fichiers de réglages de llama.cpp et d’Ollama des installations de l’app, le réglage « un ou plusieurs » de LM Studio —, un second Aperçu montre le changement, avec ce qu’il signifie et les éventuels avertissements ; Appliquer l’écrit avec une sauvegarde, et Annuler le reprend. Un nombre fixé dans ton propre script de démarrage reste tel quel. Quand les modèles sont plus nombreux que ceux gardés chargés, ou trop gros ensemble pour la carte graphique, l’état de la colonne Fournisseurs le dit aussi.

Utilisé par d'autres apps

Les LLM locaux ne servent pas qu'aux agents. Un plugin comme Video Trans, une app de chat ou ton propre script peuvent aussi leur envoyer des requêtes. L'app le remarque et le montre :

Un programme absent de la carte (ici curl) qui génère avec llama.cpp : la ligne et la boîte cyan (thème Tokyo Night). Le propre chemin de Claude Code vers opus reste dans la couleur d'accent.

  • Sur la carte, la ligne du LLM local vers le modèle avec lequel il génère devient épaisse et prend sa propre couleur, une lumière la parcourt, et la boîte du modèle reçoit un point de cette couleur et dit qui l'utilise, par exemple utilisé · Video Trans.
  • Le menu contextuel du LLM local et sa page ⓘ Détails indiquent Utilisé par Video Trans · maintenant ou il y a combien de secondes il a servi pour la dernière fois.
  • La légende ⓘ montre les deux marques.

L'app regarde lesquels de tes propres programmes ont une connexion ouverte vers le LLM local. Elle ne lit jamais ce qu'ils envoient. Un plugin apparaît sous son propre nom, un agent sous le sien, et tout le reste sous le nom de son programme. L'app elle-même et LLM Monitor, qui ne lisent que l'état, ne comptent pas.

Remarque La lumière ne se voit que pendant que le programme génère et s'éteint environ dix secondes après sa dernière requête. Un programme ouvert mais inactif — Video Trans sans parole à traduire — ne montre rien. Un programme reste dans le menu une demi-minute après sa dernière requête.

Modèles

Clic droit sur un LLM local installé › Modèles…, ou clique sur Ajouter un modèle dans Configuration. La page a une liste à gauche et le modèle choisi à droite, dans trois onglets.

Récupérer depuis Hugging Face

Parcours les modèles de chat GGUF populaires ou fais une recherche. Chaque résultat montre l'auteur, la taille, les téléchargements, les j'aime, l'ancienneté et ce qu'il sait faire : Vision, Outils, Raisonnement, MTP. La page du modèle montre les paramètres, l'architecture, le contexte, la licence et la fiche du modèle. Ce que signifie le nom explique les parties du nom, comme 35B-A3B ou Q4_K_M.

Options de téléchargement liste chaque taille avec la façon dont elle tient : dans la carte graphique, en partie en mémoire vive (fonctionne, mais plus lentement) ou probablement trop grande. Le meilleur choix est déjà fait ; Télécharger le récupère dans le dossier des modèles. Les téléchargements tournent en arrière-plan et apparaissent dans une bande en haut de la page principale. Si la connexion tombe, ils réessaient et reprennent. Si l'app a été fermée pendant un téléchargement, il est listé comme interrompu, avec Reprendre ou Abandonner.

Téléchargements interrompus

Un téléchargement de modèle ou un pull Ollama dont la connexion se coupe est relancé après 5, 15, 30, 60 et 120 secondes et reprend là où il s’était arrêté. Si l’app se ferme avant, le démarrage suivant affiche une bannière avec chaque téléchargement interrompu, où il s’est arrêté, Reprendre (il continue avec la partie déjà téléchargée) et Abandonner. Seule la façon de le relancer est gardée, dans ~/.local/state/ai-agents-map/jobs.json, lisible par toi seul ; un téléchargement qui tourne encore ailleurs n’est pas lancé deux fois.

Demander à un agent quel modèle convient

Vous ne savez pas quel modèle prendre ? Quand un agent pour les vérifications IA est configuré (Réglages › Agent pour les vérifications IA), la carte Demander à un agent sous la recherche accepte une question formulée avec vos mots — par exemple un modèle de code avec un long contexte qui tient dans ma carte graphique. Demander (ou Ctrl+Entrée) l’envoie, avec votre carte graphique, sa mémoire, la mémoire de l’ordinateur et les modèles que vous avez déjà, à cet agent, qui cherche sur le web ; pendant ce temps, un indicateur animé et le temps écoulé s’affichent. Au bout d’une à deux minutes, la carte affiche son bref résumé, et les modèles proposés apparaissent dessous dans la liste des résultats, sous le titre Proposé par … : chacun trouvé sur Hugging Face, avec sa taille et la raison pour laquelle il convient ; un clic ouvre sa page et ses options de téléchargement comme pour tout résultat de recherche. Une suggestion absente de Hugging Face est nommée sous le titre. Il propose jusqu’à 10 modèles ; Suggestions, à droite de la ligne de l’agent, règle un autre nombre (5, 10, 15 ou 20). Cela utilise les jetons de l’agent ; la question n’est pas conservée, et la page de chaque LLM local pose sa propre question.

Installés

Installés : contexte actuel, le meilleur pour ta carte et celui de l'entraînement ; ce que signifie le nom ; Retirer.

Chaque modèle montre sa taille, son fichier et son contexte — actuel, le meilleur pour ta carte et entraîné pour. Retirer demande d'abord et déplace les fichiers dans la corbeille, d'où tu peux les restaurer. Un modèle qui n'est qu'un lien ne perd que le lien.

Taille de contexte

Le contexte, c'est la quantité de texte que le modèle peut garder en tête à la fois. L'app calcule, à partir du fichier du modèle lui-même, le plus grand contexte qui tient dans ta carte graphique. Définir le contexte l'écrit dans les réglages du LLM local, avec sauvegarde et Annuler. Les agents ont besoin d'un contexte assez grand ; quand tu connectes un agent à un modèle LM Studio sans contexte défini, le meilleur est défini dans la même étape.

Sur ce PC

Liste les fichiers GGUF que le LLM local ne lit pas encore — dans son dossier des modèles, dans ceux des autres LLM locaux, dans ~/Downloads et dans ~/Models. Ajouter en fait son modèle sans deuxième copie (par un lien), sauf pour Ollama, qui importe sa propre copie.

Déplacer et supprimer des modèles

Clic droit sur un modèle de llama.cpp, KoboldCpp ou LM Studio › Déplacer vers…, ou fais glisser la boîte du modèle sur le dossier d'un autre LLM local. Tu vois d'abord combien est déplacé et quel agent utilise le modèle. Annuler remet les fichiers en place. Supprimer… demande d'abord et déplace les fichiers dans la corbeille.

Un seul dossier des modèles

Réglages › Dossier des modèles fixe un dossier pour les modèles de tous les LLM locaux. Ranger les modèles… montre à l'avance comment les fichiers seraient classés (<dossier>/<éditeur>/<modèle>/), et rien ne change tant que tu n'appuies pas sur Ranger. Avec Les anciens chemins restent valables (activé par défaut), un lien reste à chaque ancien emplacement. Annuler le dernier rangement remet tout en place.

Connecter en dessinant

Appuie sur une boîte de la carte et fais glisser jusqu'à une autre pour les connecter. Chaque modification montre, avant d'écrire, exactement quelles lignes de quel fichier changent, fait une sauvegarde et peut être annulée depuis la barre qui suit.

Agent ↔ LLM local

Fais glisser d'un agent vers un LLM local ou l'inverse. Pour modifier une connexion, sélectionne son agent (ou clique sur la ligne) : chaque ligne qu'on peut déplacer ou retirer montre un crochet orange à son extrémité. Fais glisser le crochet vers un autre LLM local — ou dans le vide pour la retirer ; survoler un crochet indique ce que fait le glisser. Trouvé sur ce PC

À chaque ouverture de la fenêtre (et avec Actualiser), l'application cherche des serveurs MCP et des dossiers de skills sur cet ordinateur, sans rien lancer : des programmes qui offrent un serveur MCP dans ~/.local/bin, ~/Applications, /opt et les dossiers ajoutés dans la Configuration, et des dossiers de skills apportés par des applications ou placés dans un dossier ajouté. Ce qu'aucun agent n'utilise encore figure sur la carte comme une case estompée sans lignes. Rien n'est connecté tout seul.

  1. Tracez une ligne d'un agent vers la case estompée.
  2. La page de connexion montre comment le serveur sera lancé — la commande que nomme son propre texte d'aide, par exemple avec un dossier qu'il peut lire et écrire — et exactement ce qui change dans les réglages de l'agent.
  3. Connecter l'écrit. La case n'est plus estompée, et l'application vérifie aussitôt que le serveur répond (voir Quand une connexion échoue).

Le serveur MCP d'une application fonctionne seul : la fenêtre de l'application n'a pas besoin d'être ouverte. Les programmes d'une AppImage pas encore décompressée ne sont pas sur la carte ; Ajouter un serveur MCP › Sur ce PC les décompresse d'abord.

Astuce Rangez les applications avec un serveur MCP et vos propres skills dans un dossier chacun — par exemple sur un disque partagé par plusieurs systèmes — et ajoutez ces dossiers dans la Configuration. Sur un autre ordinateur, ajoutez-y les mêmes dossiers : tout ce qu'ils contiennent est aussi sur sa carte.

Connexions locales

Ouvrez Connexions puis Ajouter un serveur MCP. Saisissez un nom, choisissez stdio, HTTP ou SSE et les agents installés concernés. Pour stdio, séparez l’exécutable des arguments, un argument par ligne ; les espaces restent dans l’argument. Ajoutez variables ou en-têtes par paires nom/valeur ; les valeurs sont masquées. L’aperçu montre destinataires et nombres de changements, sans valeurs de configuration. Un remplacement de définition homonyme est signalé. Appliquer utilise sauvegarde et annulation. AI Agents Map ne démarre ni ne teste le serveur ici ; les agents peuvent le démarrer en lisant la configuration.

Ajouter des compétences choisit un dossier existant contenant des dossiers avec SKILL.md. Choisissez le dossier parent et les agents, puis vérifiez liens ou paramètres. Les originaux restent en place ; les liens suivent les modifications ultérieures. Les compétences peuvent contenir des scripts exécutables par les agents. Les dossiers natifs déjà lus n’exigent pas de nouveau lien. La recherche vérifie 200 entrées par dossier, un niveau de catégories et 1 000 entrées au total ; choisissez un dossier plus petit si nécessaire. Un aperçu accepte 32 agents et 200 liens. L’annulation préserve les changements ultérieurs. Catalogues en ligne, téléchargements et vérification des outils MCP restent hors de ces formulaires locaux.

L’application cherche au démarrage, en arrière-plan et sans rien exécuter, les programmes de ce PC qui offrent un serveur MCP (leurs fichiers contiennent les mots propres au protocole ; la façon de les lancer vient de leur propre texte d’usage) et les ensembles de skills apportés par des applications. Les gros programmes sont lus une fois et mémorisés. L’état de la colonne MCP signale Nouveau sur ce PC pour ce qui n’a pas encore été montré ; Ajouter un serveur MCP… ou Ajouter des skills…, ou Trouvés sur ce PC dans Connexions, les liste, les nouveaux avec une ★. Ajouter… ouvre le formulaire rempli avec le nom et la commande de lancement, ou le dossier, à vérifier et modifier avant l’aperçu. La recherche elle-même ne lance jamais d’AppImage. Regarder dedans… ne décompresse que les programmes de chacun, enfermés par bubblewrap (pas de réseau, pas de dossier personnel, seul un dossier temporaire modifiable), les lit puis les supprime ; ce qui a été trouvé est mémorisé. Ajouter un serveur qui vit dans un AppImage demande d’abord de décompresser tout l’AppImage dans ~/Applications/<app>-<version>/ (Décompresser), de la même façon. Un AppImage plus récent d’une application déjà examinée ou décompressée est seulement nommé (Nouvelle version trouvée) : un fichier au nom plus récent ne prouve pas une vraie mise à jour, on regarde donc dedans comme pour tout autre.

Quand une application est trouvée dans une version plus récente alors que des agents, la liste des serveurs MCP ou un lien dans ~/.local/bin lancent encore l’ancienne, la liste l’affiche avec ses versions et qui l’utilise. Mettre à jour… (après avoir décompressé l’AppImage plus récent, si c’en est un) prévisualise une seule modification pour tout : chaque entrée reçoit le nouveau programme (les arguments vers l’ancien dossier suivent), les liens pointent dans le nouveau dossier et l’ancien dossier passe dans la sauvegarde. Il y reste 7 jours ; Annuler rétablit tout.

Quand une connexion échoue

Juste après l'écriture d'une connexion, l'app vérifie si elle fonctionnera : si un LLM local est installé et propose le modèle, si un serveur MCP répond, si les liens des skills sont intacts. Une connexion échouée reste sur la carte sous forme de ligne rouge en pointillés avec un ! ; une connexion avec seulement des avertissements est jaune en pointillés. Clique sur la ligne ou son ! pour des conseils :

  • Tester à nouveau la vérifie encore ; si elle passe, la ligne redevient normale.
  • Réessayer… ouvre la page de connexion pour une connexion qui n'a jamais été écrite.
  • Supprimer la connexion la retire.

Configurer un serveur

La page du serveur dit qui l'a fait et à quel point c'est vérifié, ce qu'il fait (avec des choses que tu peux demander à un agent), comment il tourne — comme programme via npx, uvx ou Docker, ou comme service web — et ce dont il a besoin, comme un dossier ou une clé API avec un lien pour l'obtenir. En dessous, Configurer :

  1. Remplis les champs dont le serveur a besoin.
  2. Coche les agents qui doivent le recevoir.
  3. Clique sur Tester pour demander ses outils au serveur.
  4. Clique sur Ajouter : tous les agents cochés sont écrits d'un coup, avec un aperçu et un Annuler.

Remarque Les valeurs secrètes, comme les clés API, sont passées dans l'environnement ou dans des en-têtes, jamais dans une ligne de commande où d'autres utilisateurs de l'ordinateur pourraient les lire. Un serveur qui aurait besoin d'un secret dans sa ligne de commande doit être configuré à la main.

Trouver des serveurs MCP… dans Connexions ouvre les onglets Recommandés (épinglés à leur version la plus récente à l’ouverture) et Registre MCP (20 résultats à la fois avec ‹ 20 précédents et 20 suivants › ; la liste du registre est téléchargée en arrière-plan pour une recherche plus rapide). La page d’un serveur indique qui l’a fait, ce qu’il fait, ce dont il a besoin et Comment il tourne ; la façon qui peut tourner sur ce PC est marquée recommandé, et un npx, uvx ou Docker manquant est nommé. Remplis les champs nécessaires (les secrets sont masqués), vérifie le Nom, coche les agents et clique sur Aperçu : l’aperçu, Appliquer et Annuler sont ceux d’un changement de connexion. Seules les valeurs saisies vont au service ; la commande elle-même vient de l’entrée du serveur et y est vérifiée à nouveau. Un secret qui se retrouverait sur une ligne de commande est refusé ; un tel serveur se configure à la main.

Tester lance une fois la façon choisie (ou interroge son adresse) et liste les outils qu’il propose, avant que rien ne soit écrit. Un serveur déjà configuré montre Outils dans sa carte sous Connexions : la dernière réponse avec sa date, et Demander au serveur (ou Redemander), qui le lance une fois comme le fait son premier agent puis l’arrête. Ses Prompts y sont aussi. La réponse est gardée pour la prochaine fois ; les clés de ses réglages vont en privé au processus qui interroge et ne sont jamais affichées.

Mises à jour trouvées

Les nouvelles versions de tes serveurs MCP, de deux sources :

  • Les vérifications IA quotidiennes (Réglages › Vérifications IA quotidiennes, désactivé par défaut) : une fois par jour, l'agent cherche sur les pages de versions officielles des versions plus récentes des serveurs dont l'app connaît la version — les apps décompressées dans ~/Applications/<app>-<version>/ ou comme AppImage décompressé dans un autre dossier (le programme dans <folder>/<app>-<version>/usr/bin/) et les paquets npm ou PyPI fixés à une version. Vérifier maintenant sur cette carte demande tout de suite, même quand les vérifications quotidiennes sont désactivées. Chaque trouvaille a Page de la version et Le faire avec … : l'agent télécharge la nouvelle AppImage dans un onglet de terminal, en demandant avant chaque étape.
  • La recherche de l'app elle-même : une version plus récente est déjà sur ce PC, mais un agent démarre encore l'ancienne (la même chose que la mise à jour sur la carte du serveur dans Configuration).

Une fois la nouvelle version sur ce PC, sa ligne le dit et propose L'utiliser… : l'aperçu de la mise à jour montre quels agents passent à elle ; Mettre à jour les modifie tous, garde l'ancienne version avec la sauvegarde et teste ensuite chaque serveur. Un serveur dont tous les agents démarrent la nouvelle version disparaît de la liste.

Pendant qu'un agent travaille

Chaque exécution d'aide IA que tu lances — Vérifier maintenant, Demander à un agent sur les pages Modèles et Ajouter un serveur MCP, Vérifier maintenant pour les mises à jour, Demander sur la carte Performances d'un LLM local — affiche une boîte au milieu de la fenêtre : qui est interrogé (l'agent et son modèle), ses étapes (un indicateur animé qui devient ✓, ou ✗ quand une a échoué), le temps écoulé et, à la fin, les jetons utilisés.

  • En arrière-plan masque la boîte ; l'exécution continue, et un message dit quand elle est terminée.
  • Annuler arrête l'agent tout de suite (son programme et tout ce qu'il a lancé).
  • En cas d'échec, la boîte reste avec ce qui n'a pas marché jusqu'à ce que tu la fermes ; le texte peut être sélectionné et copié.

Les recherches sur le web (conseils de modèles, mises à jour MCP) tournent avec le web et rien d'autre : sans les serveurs MCP, connecteurs, plugins et hooks de l'agent.

L'assistant local

L'assistant tourne sans outils, sans serveurs MCP, sans extensions et sans fichiers de projet. Protocole

Chaque exécution d'aide IA est conservée, pour que toi — ou quelqu'un qui connaît bien la configuration — puisses revoir ce qui a été fait. Chaque entrée montre quand elle a tourné, l'agent et le modèle, le résultat (réussi, échoué, annulé), la durée et les jetons. Ouverte, elle montre tout le texte : les options qui ont enfermé l'agent, les étapes, chaque question exactement telle qu'elle a été envoyée avec la réponse de l'agent, ce que l'app a changé d'après la réponse (avec la sauvegarde, pour annuler à la main) et, pour une tâche dans un onglet de terminal, ce que le terminal affichait à la fin. Copier met une entrée dans le presse-papiers pour un rapport ou un second avis ; Ouvrir le dossier du protocole montre les fichiers.

Le protocole garde les 200 dernières exécutions dans ~/.local/state/ai-agents-map/ai-help/, lisibles par toi seul. Les questions contiennent des noms, des nombres et des réglages, jamais de clés ; le texte d'un terminal contient ce qui était à l'écran.

Statistiques de jetons

Les jetons utilisés aujourd'hui et sur les 30 derniers jours, un graphique par jour, et les totaux par agent et par plugin (les autres plugins Omarchy qui utilisent le même assistant IA apparaissent ici aussi). Valeur API est ce que ces exécutions coûteraient au prix de l'API, et la ligne en dessous dit si ton abonnement le couvre ou si c'est facturé sur une clé d'API. Une tâche dans un onglet de terminal compte dans la session propre de son agent ; la page de détails de l'agent montre ces jetons.

En dessous, une carte par type de tâche — la vérification de la configuration, les mises à jour de serveurs MCP, la recherche de nouveaux agents, les corrections — avec ses exécutions, ses jetons et les derniers résultats.

Les connexions, actions des agents, suppressions de modèles et modifications des extensions s’ouvrent dans une fenêtre centrée au-dessus de la page assombrie. Faites glisser ses bords ou ses coins pour changer sa taille ; un double-clic sur un bord la rétablit. La taille reste jusqu’à la fermeture de l’application, et le terminal et Demander à l’IA la partagent. Déconnecter une ligne à la souris demande seulement Appliquer ou Annuler quand il n’y a rien à signaler, puis propose d’annuler le changement. Les pages comme la vue d’ensemble des fournisseurs, Paramètres et Connexions restent des pages entières.

Vérifiez les changements avant de confirmer. La même fenêtre affiche progression et résultat ; utilisez Annuler si proposé. Retour ou Échap abandonne la vérification ou ferme une fenêtre terminée. Ces commandes ne ferment pas une tâche en cours ; seules les opérations annulables proposent Annuler. Tant qu’une fenêtre est ouverte, les boutons de l’en-tête et les touches de l’application attendent.

Paramètres › Ce qui est permis contient vos règles sur ce qui est permis, pour Demander à l’IA et pour ce que vous dessinez sur la carte : une liste Autoriser et une liste Refuser, chacune avec un +. Une règle nomme une action et, si vous le souhaitez, une catégorie, un élément et un agent. La règle la plus précise décide : un élément compte le plus, puis un agent, une catégorie, une action. Ces règles sont un garde-fou, pas un verrou : qui peut ouvrir les Paramètres peut les modifier, et un agent dans un terminal s’exécute avec votre compte.

Maîtriser le risque

Le niveau de risque est le point le plus sérieux que trouve la carte :

  • Risque élevé — il peut faire des choses sérieuses sans demander : exécuter n'importe quelle commande, ou travailler sans sandbox et sans questions. Acceptable dans un conteneur jetable ou une machine virtuelle ; sur ton propre PC, fais-le demander d'abord.
  • Risque moyen — certaines choses se font sans demander, comme modifier des fichiers du projet, ou une revue automatique décide à ta place.
  • Risque faible — il demande avant tout ce qui compte, ou ne peut pas le faire du tout.

Bonnes habitudes, quels que soient les réglages :

  • Demander d'abord pour les commandes sur ton propre ordinateur ; autorise des commandes isolées et anodines (comme git status) avec une règle d'autorisation plutôt que tout le shell.
  • Active la sandbox là où l'agent en a une (Claude Code, Codex, Cursor CLI) et laisse le réseau désactivé à l'intérieur tant qu'aucune tâche n'en a besoin.
  • Démarre les agents dans le dossier du projet, pas dans ton dossier personnel, et garde clés et mots de passe à l'écart.
  • Peu de serveurs MCP : seulement ceux que tu utilises et en qui tu as confiance. Chacun tourne avec tes droits.
  • Le travail sans surveillance (mode contournement, « YOLO », Pi avec tous les outils) se fait dans un conteneur ou une machine virtuelle.
  • Les LLM locaux sur 127.0.0.1 : leurs serveurs n'ont pas de mot de passe.

Attention Une revue automatique (le mode auto de Claude Code, assisted de Copilot, auto-review de Cursor, smart de Hermes) est une seconde IA qui juge chaque étape. Elle épargne des questions, mais c'est un jugement, pas un mur.

Les mots expliqués

Ce que change une sandbox : les commandes n'atteignent que le dossier du projet et ce que tu autorises.

Sandbox
Un espace isolé où tournent les commandes de l'agent. À l'intérieur, une commande ne peut toucher que le dossier du projet (et ce que tu autorises) — pas le reste de ton dossier personnel, tes clés SSH ou les données du navigateur, et souvent pas internet. Sans sandbox, une commande de l'agent peut faire tout ce que tu peux faire.
Approbation (demander d'abord)
Avant que l'agent ne modifie un fichier ou n'exécute une commande, il montre ce qu'il veut faire et attend ton oui ou ton non. Moins il peut faire sans demander, plus tu gardes le contrôle — et plus souvent il te demande.
Règles d'autorisation et d'interdiction
Des listes de commandes ou d'outils que l'agent peut utiliser sans demander (autoriser) ou jamais (interdire). Interdire l'emporte sur autoriser. Une règle qui autorise n'importe quelle commande shell désactive l'approbation pour le shell.
Dossier de confiance
Un dossier dans lequel tu as dit que l'agent peut travailler. Là, il utilise aussi les propres instructions et réglages du dossier, qui peuvent venir de quelqu'un d'autre quand tu clones un projet.
Accès au réseau
Si les commandes peuvent atteindre internet. Du code qui lit tes fichiers et peut envoyer des données pourrait les divulguer ; installer des paquets a aussi besoin du réseau.
Contournement (« YOLO »)
Tout sans demander et sans limites. Seulement pour une VM ou un conteneur jetable.
Revue automatique
Un second modèle d'IA laisse passer les actions anodines et demande pour le reste.
Injection de prompt
Des instructions cachées dans une page web, un fichier ou la réponse d'un outil, qui essaient de faire faire à l'agent quelque chose que tu n'as pas demandé. Demander d'abord, une sandbox et pas de réseau les arrêtent.
Masquer les secrets
Un texte qui ressemble à un mot de passe, un jeton ou une clé est masqué avant que le modèle ne le voie ou qu'il n'atterrisse dans un journal.
Outils
Ce que l'agent peut faire tout court : lire, écrire, exécuter des commandes, chercher sur le web. Un outil qu'il n'a pas ne peut pas être détourné.
Serveur MCP
Un petit programme qui donne des outils supplémentaires à l'agent. Il tourne en tant que toi, avec tes droits.
127.0.0.1 (localhost)
Une adresse que seuls les programmes de ce PC atteignent. Un serveur sur 0.0.0.0 est accessible depuis n'importe quel appareil de ton réseau.

Modules

Tout ce qu'AI Agents Map comprend d'un agent ou d'un fournisseur de LLM est un adaptateur : comment il est trouvé et installé, ses sessions, ses réglages de sécurité, ses serveurs MCP et ses skills. Dans AI Agents Map, chaque adaptateur est un module : les paquets les apportent tous, signés et désactivés, et tu actives ceux que tu utilises. Les modules apportent aussi de nouveaux agents, de nouveaux fournisseurs et des fonctions au-delà des chiffres, comme Insights (sujets des sessions et un résumé par Claude). Le plugin AI Agents Map a les adaptateurs intégrés et n'a pas de modules.

Configurer AI Agents Map

Un AI Agents Map neuf s'ouvre sur sa page d'accueil. Chaque agent et LLM local qu'AI Agents Map connaît est une carte avec sa propre icône, en trois groupes : Agents IA, LLM locaux et Fournisseurs en ligne (les noms d'Anthropic, d'OpenAI et des autres sur la carte). Chaque carte dit si le programme est là :

  • Installé (vert) — trouvé de la même façon que la carte le trouve ; la carte est déjà cochée ;
  • Utilisé auparavant — pas installé maintenant, mais ses réglages sont toujours là ;
  • Non installé — coche-le pour l'installer ensuite depuis sa carte.

La page d'accueil : les programmes trouvés viennent en premier et sont cochés.

Clique sur une carte (ou appuie sur Espace dessus) pour la cocher ou la décocher ; une carte cochée a une bordure bleue et une coche. Activer (avec le nombre de cartes cochées) les charge et montre la carte ; si tu as coché des programmes qui ne sont pas installés, Configuration s'ouvre : ⋯ sur leurs cartes › Installer…. Plus tard démarre avec une carte vide. Tant que rien n'est activé, AI Agents Map se rouvre sur la page d'accueil à chaque démarrage. Ensuite, les mêmes cartes se trouvent dans Configuration (le bouton de l'en-tête), où agents et fournisseurs s'activent et se désactivent à tout moment.

À chaque démarrage suivant, AI Agents Map regarde de nouveau ce qui est installé et active de lui-même le module de chaque agent, LLM local et fournisseur en ligne qu'il trouve, pour qu'ils soient tous sur la carte. Un module que tu as désactivé toi-même (ici, sur la page des modules ou laissé décoché sur la page d'accueil) reste désactivé ; réactive-le pour le retrouver.

La page des modules

Ouvre-la avec le bouton pièce de puzzle de l'en-tête, depuis Réglages › Modules ou depuis n'importe quel conseil « module disponible ». Elle montre, dans des cartes de groupe repliables qui commencent ouvertes :

  • Suggérés pour ce PC — un module dont l'agent ou le fournisseur est installé ici mais pas encore affiché ;
  • Modules installés — activé, désactivé ou non chargé avec la raison (par exemple un fichier modifié) ; les agents et les fournisseurs séparés par une ligne ;
  • Disponibles — le reste des modules du catalogue ;
  • Intégré à AI Agents Map — les agents et fournisseurs qu'aucun module installé n'apporte (quand tu lances AI Agents Map depuis son dossier source sans modules).

Installer, activer et désactiver, mettre à jour, retirer

Installer (ou Obtenir le module) montre d'abord ce que le module lit, envoie et peut faire ; ce n'est qu'après ton accord qu'il est téléchargé, vérifié et activé. Désactiver et Activer agissent aussitôt, sans redémarrage : ses agents, fournisseurs, sections et cartes apparaissent ou disparaissent partout. Mettre à jour le remplace par la version plus récente du catalogue après vérification de la nouvelle ; Retirer le déplace dans la corbeille. Installer depuis un fichier… prend un zip de module que tu as téléchargé toi-même ; les mêmes vérifications s'appliquent.

Quand le catalogue a des versions plus récentes de modules installés, les cartes de la Configuration indiquent Mise à jour de l’extension, l’état de la colonne affiche Mises à jour de modules prêtes avec Tout mettre à jour et Modules, et la page des modules montre une barre avec Tout mettre à jour. Le menu ⋯ de la carte (ou un clic droit dessus) propose aussi Mettre à jour l’extension vers version, pour cette seule extension. Tout mettre à jour les met à jour l'un après l'autre, avec les mêmes vérifications, et dit en un seul message lesquels l'ont été. Une seule installation ou mise à jour tourne à la fois ; une autre lancée entre-temps demande de réessayer dans un instant.

Seulement de l'auteur. AI Agents Map ne charge que des modules signés par Uwe Bruckhaus (empreinte de la clé SHA256:e5cC634Ke3Our5LAeSc88qs22NKZEHTncBW5Ig3amWQ). Avant que quoi que ce soit d'un module ne tourne, la signature est vérifiée avec ssh-keygen d'OpenSSH, chaque fichier est comparé à sa somme SHA-256, et aucun fichier ne doit avoir été ajouté. Un téléchargement doit en plus correspondre à la somme SHA-256 du catalogue signé.

Créer un module

Un nouveau LLM local ou un nouvel agent n'a besoin que d'un module : AI Agents Map construit sa carte, sa boîte et ses lignes sur la carte, ses détails, la page Modèles et la page Sécurité à partir de ce que le module en dit. Si tu sais un peu programmer, pars des modèles du dépôt d'AI Agents Map (templates/, expliqués dans docs/addons.md) : un fichier pour un LLM local, un fichier de faits pour un agent. Confidentialité et sécurité

  • Aucun droit d'administrateur pour l'app. Elle ne tourne jamais en root et ne voit jamais de mot de passe. Installer un agent fourni comme paquet du système (comme Hermes ou OpenClaw) lance le gestionnaire de paquets du système avec sudo dans un terminal que tu vois, après t'avoir montré la commande.
  • Aucun identifiant lu. Elle lit les réglages des agents, mais jamais leurs fichiers d'identifiants. Qu'un agent soit connecté se voit à l'existence d'un tel fichier. Les valeurs des clés et des en-têtes ne sont jamais affichées.
  • Aucune conversation lue. Les chiffres d'utilisation ne sont lus que comme des nombres et des durées. La seule exception est le suivi d'une instance En arrière-plan (Terminaux…), sur ton clic, pour cette instance seulement ; rien n'en est conservé.
  • Le réseau seulement quand tu le demandes — chercher ou installer des modèles, des serveurs MCP ou des skills, tester un serveur —, plus une vérification des mises à jour toutes les quelques heures.
  • Téléchargements vérifiés. Les programmes ne sont installés que si le téléchargement correspond à la somme publiée par leur version.
  • Aperçu et Annuler. Chaque modification des réglages d'un autre programme est montrée avant, sauvegardée et peut être annulée. Les réglages pouvant contenir des clés sont écrits lisibles par toi seul.
  • Encadré. Chaque programme tourne sans shell, et chaque réponse est lue avec une limite de taille et de temps.
  • Les fonctions IA seulement quand tu les choisis. Les recherches de Smart Check se font sur un clic, les vérifications IA quotidiennes seulement quand elles sont activées. L'agent reçoit un court résumé (noms, versions, modèles), jamais de clés ni de valeurs de réglages, transmis d'une façon que les autres utilisateurs de l'ordinateur ne peuvent pas lire ; ses réponses sont vérifiées avant d'être affichées et ne sont jamais exécutées. Les tâches tournent dans un terminal que tu vois, et l'agent demande avant chaque étape. Tu les utilises à tes propres risques.

Le README de chaque dépôt liste en entier ce qui est lu, démarré et écrit.

Glossaire

Approbation
Un agent demande avant de modifier un fichier ou d'exécuter une commande (voir Les mots expliqués).
Contexte
Combien de jetons de texte un modèle peut garder en tête à la fois.
GGUF
Le format de fichier de modèles utilisé par llama.cpp, LM Studio, Ollama et KoboldCpp.
Injection de prompt
Des instructions cachées dans une page, un fichier ou la réponse d'un outil qui essaient d'orienter un agent.
Quantification
Stocker un modèle avec moins de bits par poids (par exemple Q4_K_M, environ 4,8 bits) pour qu'il soit plus petit, avec une faible perte de qualité.
Mélange d'experts
Un modèle où seule une partie des paramètres travaille pour chaque jeton (35B-A3B : 35 milliards au total, 3 milliards actifs), ce qui le rend rapide pour sa taille.
Sandbox
Un espace isolé où tournent les commandes d'un agent, qui n'atteignent que le dossier du projet et ce qui est autorisé.
Jeton
Un morceau de texte, environ les trois quarts d'un mot, que les modèles lisent et écrivent.
Service utilisateur
Un programme d'arrière-plan que systemd démarre pour ton utilisateur seulement, sans droits d'administrateur.
