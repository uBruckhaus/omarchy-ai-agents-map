Über dieses Handbuch

Dieses Handbuch beschreibt AI Agents Map, ein Plugin für den Omarchy-Desktop: Eine Schaltfläche in der Leiste öffnet es. Es nutzt die Farben des Omarchy-Themes (oder GNOMEs Adwaita-Look) und speichert seine Einstellungen in ~/.config/omarchy/ai-agents-map/.

Inhalt

Einführung

AI Agents Map zeigt das KI-Setup deines Computers als Karten und als Karte: welche Coding-Agenten installiert sind, welche Sprachmodelle sie nutzen — Cloud-Dienste und lokale Laufzeiten —, welche Modelle diese bereitstellen und welche MCP-Server und Skills jeder Agent hat. Und es lässt dich dieses Setup durch Linienzeichnen ändern.

Das Hauptfenster: die Karte über die ganze Breite, darüber die GPU-Karte, in der Kopfzeile das ! für offene Probleme.

Was es kann

  • Coding-Agenten — Claude Code, Codex, GitHub Copilot, Cursor CLI, Gemini, OpenCode, Pi, Hermes und mehr: ihre Version, ihr Abo, ihre Limits und ihre Nutzung, und was jedem noch fehlt, mit dem Befehl, der es behebt.
  • Lokale LLMs — llama.cpp, Ollama, LM Studio, vLLM, Jan, KoboldCpp und Strata: installieren, Modelle herunterladen, die zur Grafikkarte passende Kontextgröße einstellen und sie zusammen mit den Agenten starten, die sie nutzen.
  • MCP-Server und Skills — gefunden auf deinem Computer oder im Web, mit empfohlenen Servern und einer Suche in der offiziellen MCP-Registry.
  • Spaltenstatus — ein Symbol an der KI-fragen-Leiste jeder Spalte, jedes Problem mit dem Weg dorthin, wo es behoben wird; wofür sich deine Einrichtung eignet, steht auf der Willkommensseite und in der Hilfe.

Grundbegriffe

Agent
Ein Programm, mit dem du sprichst und das Code schreibt oder Aufgaben erledigt, etwa Claude Code.
LLM-Anbieter
Wo das Modell eines Agenten läuft: ein Cloud-Dienst (Anthropic, OpenAI, …) oder eine lokale LLM-Laufzeit auf diesem Computer (llama.cpp, Ollama, …).
Modell
Das Sprachmodell selbst. Lokale Modelle sind Dateien, meist im GGUF-Format.
MCP-Server
Ein kleines Programm oder ein Webdienst, der Agenten zusätzliche Werkzeuge gibt — Dateien lesen, im Web suchen, einen Browser steuern. MCP ist das Model Context Protocol.
Skill
Ein Ordner mit Anweisungen (einer SKILL.md) und manchmal Skripten, die einem Agenten eine bestimmte Aufgabe beibringen.

Nichts ändert sich ohne Vorschau

Jede Änderung an den Einstellungen eines Agenten wird zuerst Zeile für Zeile gezeigt, bevor etwas geschrieben wird. Die alte Datei bleibt als Sicherung erhalten, und die Leiste, die nach der Änderung erscheint, hat Rückgängig. Die App selbst läuft nie mit Administratorrechten; nur das Installieren eines Agenten, der als Systempaket kommt, fragt nach deinem Passwort, in einem Terminal, das du siehst.

Installation

Das Plugin installieren

Installiere AI Agents Map aus dem Omarchy Plugin Marketplace oder in einem Terminal:

omarchy plugin add https://github.com/uBruckhaus/omarchy-ai-agents-map.git --enable

In der Leiste erscheint eine Roboter-Schaltfläche. Alles andere, was es braucht, bringt eine normale Omarchy-Installation mit, seine signierten Add-ons eingeschlossen. Damit Agenten im Fenster laufen, installiere VTE: sudo pacman -S vte4. Optional: mise installiert und aktualisiert Agenten.

Erster Start

Eine neue Installation öffnet die Willkommensseite: Die auf diesem Computer installierten Agenten und lokalen LLMs sind bereits angehakte Karten, und Einschalten bringt sie auf die Karte (siehe AI Agents Map einrichten). Nach einem Update von einer früheren Version des Plugins bleiben deine Einstellungen erhalten, und die Add-ons der Agenten und lokalen LLMs auf diesem Computer werden von selbst eingeschaltet, sodass die Karte zeigt, was sie vorher zeigte.

Die Schaltfläche in der Leiste öffnet das Fenster, holt es nach vorn oder blendet es aus, wenn es schon vorn ist. Schließen blendet das Fenster aus; das Programm läuft im Hintergrund weiter und öffnet sich deshalb sofort wieder. Einstellungen › Im App-Starter legt einen Eintrag im App-Starter von Omarchy an.

Hinweis Solange ein Agent im Fenster läuft, fragt das Schließen zuerst: Stoppen und schließen (dann stoppt auch das lokale LLM des Agenten und gibt den Speicher der Grafikkarte frei) oder Weiterlaufen lassen.

Während die App beim ersten Öffnen nachsieht, was auf diesem Computer ist, listet eine animierte Übersicht auf, was sie findet, Art für Art: Agenten, lokale LLMs, MCP-Server und Skills, jeweils mit einem Drehsymbol, das zu ✓ und einer Zahl wird, und wie viele davon noch nicht verbunden sind. Sie blendet sich nach einem Moment von selbst aus; ein Klick schließt sie sofort.

Das Plugin entfernen

omarchy plugin remove ubruckhaus.ai-agents-map.

Schalte vor dem Entfernen Einstellungen › Lokale LLMs mit ihren Agenten starten aus, damit auch der Wächter im Hintergrund entfernt wird, und Einstellungen › Im App-Starter, um den Eintrag im App-Starter zu löschen. Was du mit der App geändert hast, bleibt: Einstellungen der Agenten, MCP-Server, Skills und installierte lokale LLMs. Deinstalliere ein lokales LLM vorher (Rechtsklick › Deinstallieren…), wenn es weg soll. Um auch den eigenen Zustand der App zu löschen:

rm -rf ~/.config/omarchy/ai-agents-map ~/.local/state/ai-agents-map \
       ~/.cache/ai-agents-map ~/.local/share/ai-agents-map/addons

Setup

Die Karte zeigt, was eingerichtet ist — installierte Agenten und lokale LLMs, die MCP-Server und Skill-Ordner, die Agenten nutzen, und Modelle — und, blass, die auf diesem Computer gefundenen MCP-Server und Skill-Ordner, die noch kein Agent nutzt, bereit zum Verbinden mit einer Linie (siehe Auf diesem PC gefunden). Alles andere geschieht im Setup (die Schaltfläche in der Kopfzeile neben Karte), eine Karte pro Eintrag, in Abschnitten, die sich mit einem Klick auf ihre Leiste einklappen:

  • Wie etwas auf deine Karte kommt — eine zugeklappte Karte ganz oben; öffne sie für fünf nummerierte Schritte: einschalten (oder finden), was du nutzt, installieren, was fehlt, bei einem Online-Agenten anmelden, durch Zeichnen verbinden, und was von selbst erscheint.
  • Was du damit machen kannst — wofür das Setup taugt (Alltagshilfe, Programmieren, Bilder, Sprache, Recherche und Schreiben), je eine Kachel mit dem, was da ist, und dem nächsten Schritt; zugeklappt sagt ihre Zeile, wie viele bereit sind.
  • KI-Agenten, Lokale LLMs — alle, die die App kennt. Eine Karte mit blauem Rahmen ist auf diesem PC installiert; eine graue nicht, und sie hat Installieren, wo installierte Deinstallieren haben. Ein Klick hakt die Karte an oder ab (✓), dann schaltet Übernehmen ihr Add-on ein oder aus. Ausschalten nimmt sie von der Karte; gelöscht wird nichts. Solange ein Agent in einem Terminal von AI Agents Map läuft (auch dem von KI fragen), lässt sich sein eigenes Add-on nicht ausschalten, aktualisieren oder entfernen; alle anderen Add-ons lassen sich ändern. Die Seite nennt den Agenten und hat Terminal zeigen.
  • Online-Anbieter — das Add-on der Online-Anbieter; sein Menü hat Anmelden bei … für jeden installierten Agenten, der sie nutzt.
  • MCP-Server, Skills, Modelle — eine Karte für jeden installierten Eintrag. Ein Klick öffnet seine Details (bei einem Modell sein Menü). Die Karte mit + am Ende eines Abschnitts fügt einen hinzu: MCP-Server hinzufügen, Skills hinzufügen, Modell hinzufügen, Add-ons holen.
  • ⋯ oder ein Rechtsklick auf eine Karte öffnet dasselbe Menü wie das Feld auf der Karte: aktualisieren, anmelden, starten oder stoppen, Details, deinstallieren oder entfernen, ein Modell verschieben.
  • Ein gelbes ↑ Version auf einer Karte heißt, dass ein Update bereitsteht; ihr Menü hat Aktualisieren.
  • Ein rotes ! auf einer Karte heißt: Dort gibt es ein offenes Problem; zeige mit der Maus darauf, um zu sehen, welches.
  • Die Details eines Agenten zeigen unter dem Tarif Zusätzliche Nutzung: ob über die Limits des Tarifs hinaus zusätzlich Geld anfallen kann. Claude Code hält das auf deinem PC fest (mit der Seite zum Ändern); bei anderen Agenten sagt die App, dass sie es nicht weiß, prüfe es dann beim Anbieter.
  • Eine kleine Batterie auf der Karte eines Online-Agenten zeigt, was von seinen Limits übrig ist (eine Sitzung, eine Woche): Das knappste zählt, gelb bei einem Viertel oder weniger, rot unter einem Zehntel; zeige mit der Maus darauf für jedes Limit und wann es zurückgesetzt wird. Auf der Karte eines laufenden lokalen LLMs ist die Batterie der noch freie GPU-Speicher, in denselben Farben; zeige mit der Maus darauf, um zu sehen, wie viel dieses lokale LLM belegt.
  • Das Aktualisieren-Symbol (F5) in der Kopfzeile sieht erneut nach, was installiert, eingerichtet und angemeldet ist, und führt die Prüfungen eines Starts noch einmal aus (neue Apps, Add-ons, Updates, offene Probleme).

Setup: Installierte Agenten haben einen blauen Rahmen, eingeschaltete ein ✓, Updates ein gelbes und Probleme ein rotes Abzeichen; das Menü von Claude Code.

MCP-Server und Skills, jeder Abschnitt mit einer Karte zum Hinzufügen.

Es gibt nichts zu verstecken: Was du nicht auf der Karte willst, wird hier ausgeschaltet oder entfernt. Läuft eine Installation oder eine Anmeldung in einem Terminal im Fenster, führt Zurück (oder × auf ihrem Reiter) zu der Seite zurück, auf der sie gestartet wurde.

Lokale MCP-Server und Online-MCP-Server (solche, die über eine Webadresse erreicht werden) sind zwei Abschnitte. Ordner hinzufügen… in Lokale MCP-Server und in Skills fügt einen Ordner hinzu, in dem die App ebenfalls danach sucht — zum Beispiel eine gemeinsam genutzte Platte mit entpackten Apps, die einen MCP-Server anbieten, oder ein Ordner mit eigenen Skills. Die hinzugefügten Ordner stehen neben der Schaltfläche; ✕ bei einem beendet die Suche dort (darin wird nichts gelöscht). Was darin gefunden wird, erscheint blass auf der Karte, bis eine Linie es verbindet: Das Setup hat nur Karten für das, was eingerichtet ist.

Auswählen, was die Karte zeigt

Die Karte zeigt alles, was eingerichtet ist. Die Filterknöpfe MCP-Server, Agenten, Anbieter und Modelle über der Karte (und Einstellungen › Karte) lassen ganze Spalten weg und werden gemerkt.

In einem kleinen Fenster (bis 55 % des Bildschirms oder unter 1150 Pixeln) zeigt die Karte Agenten und Anbieter; in einem mittleren Fenster (bis 80 % des Bildschirms oder unter 1600 Pixeln) kommen Modelle hinzu; in einem größeren Fenster zeigen sich alle vier Spalten. Eine Spalte, die die Ansicht auslässt, lässt sich mit ihrem Knopf über der Karte trotzdem einschalten, und die Karte ordnet sich neu an; der Filter blendet Spalten in jeder Ansicht aus. Die gezeigten Spalten sind zentriert und passen ihre Breite (266 bis 560 Pixel) und den Abstand an den freien Platz an, und die Karte passt sich an die Fensterbreite an, bis du zoomst (Strg+0 passt sie wieder an).

Mit der Karte arbeiten

Das Modell eines Agenten ist eine Kette: eine Linie vom Agenten zu seinem Anbieter und eine vom Anbieter zum genutzten Modell. Modelle, die niemand nutzt, bleiben Kästen ohne Linie, und der Filter einer Karte (nur Verbundenes oder Angeheftetes) blendet sie aus. Einen lokalen Anbieter auf eines seiner Modelle zu ziehen ist ein kurzer Schritt: Der Anbieter nutzt dieses Modell, und ein Agent, den du später mit dem Anbieter verbindest, bekommt es. Kann ein Ablegen nicht funktionieren, sagt ein kurzer Hinweis warum, etwa mit welchem Anbieter der Agent zuerst verbunden sein muss. Eine einfache gezeichnete Verbindung oder Trennung fragt in einem kleinen Dialog nach Anwenden und bestätigt danach mit einem kurzen Hinweis samt Rückgängig; ein Fehler sagt, was schiefging. Weitere Schritte verwenden die ausführliche Vorschau. Wenn ein Agent einen anderen aufruft, bekommen dessen aktive Linien und der Pfeil zwischen ihnen eine eigene Farbe, auch bei weiteren Aufrufen. Der Pfeil zeigt auf den genutzten Agenten; nach der Arbeit bleibt er blass. Das Baumsymbol auf einer Agentenkarte öffnet die letzten Unteragenten; es leuchtet während ihrer Arbeit und ist bei nur abgeschlossenen Unteragenten blass.

KI fragen kann dieselben Kartenänderungen vorschlagen, darunter den Wechsel eines vorhandenen Modells, das Verbinden eines Skill-Ordners, das Reparieren einer fehlerhaften Verbindung und die An- oder Abmeldung eines Agenten. Dieselbe Vorschau fragt vor dem Anwenden. Bei Fragen zu Geschwindigkeit, Grafikspeicher, Kontextgröße, Vulkan oder ROCm öffnet KI fragen Leistung und prüft Hardware und Messwerte dieses PCs vor einem Vorschlag.

Unter dem Fragefeld zeigt eine scrollbare Karte Beispiele für MCP-Server und Skills, Agenten, Anbieter und Modelle. Ein Beispiel trägt die Frage mit der Kategorie am Anfang ein (etwa Modelle:) und wechselt zu ihr; es sendet noch nichts. Du kannst die Frage ändern oder selbst eine Kategorie eingeben. Erst Fragen sendet sie. In der Statusansicht bleiben die Befunde jeder Kategorie einzeln erreichbar.

Die Beispiele lassen sich anpassen: Das Lesezeichen im Fragefeld speichert das Getippte als neues Beispiel der gewählten Kategorie (bis zu 12 je Kategorie), der Stift neben einem Beispiel bearbeitet es direkt (Enter übernimmt, Esc bricht ab, ein leerer Text entfernt es), sein × entfernt es, und der Pfeil am Ende der Zeile holt die eingebauten Beispiele zurück.

Spaltenstatus

Die KI fragen…-Leiste jeder Spalte zeigt links deren Zustand, und die Kopfleiste zeigt den schlechtesten Zustand aller Spalten, auch einer ausgeblendeten: ein grünes Häkchen, wenn alles in Ordnung ist, ein gelbes Dreieck bei Tipps, Updates oder Vorschlägen, ein rotes !, wenn etwas zu beheben ist. Ein Klick auf das Symbol öffnet die Liste der Spalte, das Wichtigste zuerst: ein nicht angemeldeter Agent, ein lokales LLM ohne Modelle, eine Verbindung, die nicht funktioniert, wenig Platz für Modelle, jeweils mit einer Schaltfläche dorthin, wo es behoben wird. KI fragen an einer Zeile setzt sie in die Eingabe; erst Fragen schickt sie ab. Ein Klick auf das Symbol in der Kopfleiste führt zur ersten betroffenen Spalte. Die Prüfung liest nur; sie ändert, startet und sendet nichts.

Die Liste zeigt auch neue Programme oder Skills auf diesem PC, was auf diesem PC, aber nicht auf der Karte ist, und Updates für installierte Agenten, lokale LLMs und MCP-Server, jeweils mit ihrer Schaltfläche. Updates werden beim Öffnen des Fensters im Hintergrund geprüft, höchstens alle sechs Stunden. Ein Update startet erst, wenn du auf Aktualisieren klickst (siehe Gefundene Updates). Wofür sich deine Einrichtung eignet, steht auf der Willkommensseite und in der Hilfe, unter Was du damit machen kannst.

Smart-Karten auf der Karte

In AI Agents Map steht oben in jeder Kartenspalte eine eingeklappte Leiste KI fragen… mit einem Statussymbol links: einem grünen Häkchen, wenn alles in Ordnung ist, einem gelben Dreieck bei Hinweisen, Updates oder Vorschlägen oder einem roten !, wenn in dieser Spalte etwas zu beheben ist. Die Kopfleiste zeigt den Gesamtstatus über alle vier Spalten (auch ausgeblendete) und öffnet die erste betroffene Spalte. Ein Klick auf das Statussymbol einer Spalte öffnet deren Statusliste: jeden Befund dieser Spalte mit dem Knopf dorthin, wo er behoben wird, und KI fragen zum Vorbelegen des Eingabefelds, neuere Versionen installierter Agenten und lokaler LLMs (Aktualisieren startet mise upgrade oder den eigenen Updater des Agenten in einem Terminal oder öffnet die Installationsvorschau; geprüft höchstens alle sechs Stunden), MCP-Server-Updates aus den täglichen KI-Prüfungen sowie Erneut prüfen. Auf der Willkommensseite zeigt Was du damit machen kannst die Anwendungsfälle (Hilfe am PC, Vibe Coding, Bilder, Sprache, Recherche und Schreiben) als Bereit, Fast oder Noch nicht, mit dem, was dafür da ist, und dem nächsten Schritt.

Beim Start liest die App im Hintergrund den signierten Add-on-Katalog: aus ihrem Zwischenspeicher, und online nur, wenn Online nach Add-ons suchen an ist. Die letzten 50 Projektordner werden pro Agent gespeichert.

Das Start-Untermenü jedes Agenten hat drei durch Linien getrennte Bereiche: Start mit dem aktuellen Ordner, Ordner wählen… und die durchsuchbare Liste Zuletzt verwendete Projekte.   • Im Terminal starten öffnet ihn in einem eigenen Terminalfenster.

Agenten, die zusammenarbeiten

In AI Agents Map ist ein Agent, der einen anderen gestartet hat und ihn nutzt — etwa Claude Code, das über seine Shell pi -p … ausführt —, auf der Karte durch eine Linie mit ihm verbunden, die rechts an den Agenten-Kästen entlang gebogen ist. Beides wird jede Minute neu angesehen. Eine Batterie, deren Zahlen vielleicht nicht mehr aktuell sind (der Sammler hat sie nach einer fehlgeschlagenen Abfrage behalten, oder sie wurden vor mehr als 30 Minuten gemessen), ist blass, und ihr Tooltip sagt, wann sie gemessen wurden; ein Limit ohne Zeitpunkt für das Zurücksetzen wird dann nicht mehr gezeigt. Gefragt wird nur das installierte Codex, nie ein Starter, der es erst installieren oder aktualisieren würde; eine Anmeldung im Schlüsselbund oder in dem Ordner, den CODEX_HOME nennt, zählt auch. Solange die App offen ist, werden die Limits alle zehn Minuten neu erfragt; nach einer Abmeldung werden sie nicht mehr gezeigt. AI Agents Map liest selbst keine Anmeldedateien; das tut der Sammler oder der Agent. Ein Agent, dessen eigene Sitzungsdaten sagen, was seine Sitzungen gekostet haben (Hermes, OpenCode), gilt als pro Token bezahlt; ein bloß geschätzter Betrag zählt nicht. API-Schlüssel

In AI Agents Map zeigt ein Agent, der einen API-Schlüssel liest, in seinen Details API-Schlüssel…. Mit den Agenten starten und stoppen

Verbinde einen Agenten einmal mit einem lokalen LLM und starte dann einfach den Agenten — auch bei geschlossener App oder nach einem Neustart. Sein lokales LLM startet mit, und wenn der letzte Agent, der es nutzt, beendet wird, stoppt das LLM etwa fünf Sekunden später, sodass sein Grafikspeicher wieder frei ist.

Das erledigt ein kleiner Hintergrunddienst, ai-agents-map-providers.service. Er wird mit der ersten Verbindung zu einem lokalen LLM eingerichtet und entfernt, wenn die letzte wegfällt oder wenn du Einstellungen › Lokale LLMs mit ihren Agenten starten ausschaltest.

Hinweis KoboldCpp braucht ein paar Sekunden zum Starten, länger als manche Agenten warten. Darum startet es beim Anmelden, und wenn der letzte Agent beendet wird, wird nur sein Modell entladen.

Hinweis Strata startet nicht mit seinen Agenten. Starte es auf der Karte (die Schaltfläche ▶ an seinem Kasten) oder in Strata selbst, bevor du mit einem damit verbundenen Agenten arbeitest.

Strata

Strata ist eine lokale Inferenz-Engine mit einer eigenen Terminal-App. Es stellt jeweils ein Modell auf 127.0.0.1:8080 bereit und spricht die OpenAI- und Anthropic-APIs, sodass sich Agenten damit verbinden wie mit den anderen lokalen LLMs. AI Agents Map findet es an seinem eigenen Befehl strata (ein anderes Programm dieses Namens, etwa der Strata-Dateimanager in /usr/bin, wird nicht dafür gehalten), an seinem laufenden Server und an seinen Modellen: den Run-Configs, die Strata in ~/.local/share/strata/install ablegt.

Ein Modell auswählen, herunterladen und abstimmen geschieht in Stratas eigenen Bildschirmen: führe ~/.local/bin/strata launch in einem Terminal aus (~/.local/bin/strata launch --status zeigt, was gerade läuft). Hat Strata so einmal ein Modell gestartet, merkt es sich das als Launch-Preset. Ab dann startet Starten auf der Karte (die Schaltfläche ▶ an Stratas Kasten) das zuletzt genutzte Preset (strata launch --preset … --no-tui, das zurückkehrt, sobald das Modell bereitsteht; große Modelle brauchen ein paar Minuten), und Stoppen stoppt es (strata launch --stop).

Strata und llama.cpp nutzen beide Port 8080, sofern nichts anderes eingestellt ist. Ein Agent, der auf der Karte verbunden wurde, nennt sein lokales LLM (strata-local), bleibt also bei Strata, auch wenn llama.cpp diesen Port ebenfalls nutzt; auf einem Port kann jeweils nur eines von beiden bereitstellen.

AI Agents Map entfernt Strata nicht. Um es selbst zu entfernen, lösche sein Terminal (~/.local/share/strata/terminal) und den Link ~/.local/bin/strata. Seine Engines und Run-Configs liegen in ~/.local/share/strata (components, install), seine Modelle in den Ordnern, die du in Strata gewählt hast, und die Chats der Desktop-App in ~/.strata; lösche sie nur, wenn du sie nicht mehr brauchst.

Details eines lokalen LLMs

Klicke die Karte eines lokalen LLMs im Setup an, oder Rechtsklick auf sein Feld auf der Karte › Details. Unter den Kacheln (Modelle, Agenten, Adresse) folgen dieselben zuklappbaren Karten wie bei Agenten: Nutzung und Tokens — was deine Agenten in den letzten Tagen darüber geschickt haben, pro Agent und Modell, aus den eigenen Sitzungszahlen der Agenten und über den Modellnamen zugeordnet —, dann Zustand, Risikomanagement, Was die Begriffe bedeuten und Konfiguration.

Leistung

Ein lokales LLM, dessen Einstellungen die App kennt (llama.cpp, Ollama von der App installiert), hat auf seiner Detailseite eine Karte Leistung:

  • Variante, GPU-Stacks und Grafikspeicher: womit es läuft — ROCm, Vulkan, CUDA oder die CPU (bei llama.cpp aus seiner eigenen Geräteliste gelesen, auch bei einer selbst gebauten Variante), welche dieser Stacks dieser PC hat, und der Speicher der Karte.
  • Kontext pro Modell: für jedes Modell die Dateigröße, der jetzt eingestellte Kontext, der Kontext, den die Karte dafür fasst — seine Datei plus der Cache des Kontexts, aus dem Header des Modells gelesen — und wofür es trainiert wurde. ! markiert einen Kontext, der größer ist, als die Karte fasst (das Modell würde nicht laden oder in den RAM ausweichen), ↑ einen, den die Karte größer machen könnte; Auf … setzen ändert ihn.
  • … fragen: Der lokale Helfer (oder der Online-Agent) sieht sich diese Fakten an — nur Namen und Zahlen — und schlägt Änderungen vor: Einstellungen wie Flash Attention, den Cache-Typ des Kontexts, die GPU-Layer, parallele Anfragen und Batch-Größen; Kontexte; eine andere Variante, wenn sie klar helfen würde. Die App behält nur Vorschläge, hinter denen sie stehen kann (eine bekannte Einstellung mit erlaubtem Wert, ein Kontext, den die Karte fasst), und zeigt jeden mit Begründung. Übernehmen schreibt ihn mit Sicherung; die Meldung bietet Rückgängig an, oder Jetzt neu starten, wenn er erst nach einem Neustart zählt. Eine andere Variante wird nur vorgeschlagen: Installiere sie über das Menü des lokalen LLMs.

Bei Ollama gelten seine Einstellungen für alle Modelle zugleich (die Umgebungsdatei seines Servers).

In AI Agents Map hat ein lokales LLM mit Einstellungen, die die App abstimmen kann (llama.cpp, Ollama), unter Anbieter und Modelle den Knopf Leistung. Er zeigt die Variante, als die es läuft, die GPU-Stacks auf diesem PC und den Grafikspeicher, dann Kontext pro Modell: die Größe jedes Modells, seinen Kontext jetzt, was die Karte für es fasst und wofür es trainiert wurde. Ein Modell mit mehr Kontext, als die Karte fasst, ist markiert, ebenso eines, für das die Karte noch Platz hat; bei llama.cpp setzt Auf … setzen ihn. Einstellungen für alle Modelle listet die Einstellungen der Engine mit ihrer Wirkung; eine mit einer Liste von Werten lässt sich dort ändern. Jede Änderung wird zuerst gezeigt und mit einer Sicherung geschrieben, sodass Rückgängig sie zurücksetzt; sie zählt nach einem Neustart des lokalen LLMs. Unter Tipps von einem Agenten lässt … fragen den Agenten für KI-Prüfungen auf diese Fakten schauen (nur Namen und Zahlen, nur über das Web): Er schlägt Einstellungen, Kontexte, einen anderen Build oder Hinweise vor, jeweils mit Begründung. Die App behält nur, was sie vertreten kann — einen erlaubten Wert, einen Kontext, den die Karte fasst, einen Build, den das lokale LLM hat —, und Übernehmen geht durch dieselbe Vorschau. Die Tokens sind die des Agenten; der Lauf steht im Smart Check. Für llama.cpp misst die App außerdem jedes Modell auf dieser Grafikkarte mit dem Build, den sein Dienst nutzt (ROCm oder Vulkan): nach einem Download, wenn sich der Build ändert, und mit Messen und einstellen. Sie probiert Batch-Größen aus, behält die schnellste und gibt dem Modell den größten Kontext, den der gemessene Videospeicher übrig lässt, mit q8_0-Cache und Flash Attention, sofern du nichts anderes gewählt hast; mit llama.cpp verbundene Agenten bekommen den neuen Kontext ebenfalls. Solange ein Modell geladen ist, wartet sie, und Rückgängig stellt die alten Einstellungen wieder her.

GPU-Speicher und GPU-Speicher freigeben

In der GPU-Karte über der Karte zeigt GPU-Speicher, wie viel belegt ist, aufgeteilt in lokale LLMs, Desktop und Apps und frei; GPU-Aktivität zeigt Last, Temperatur und Leistung. Das Feld jedes lokalen LLMs zeigt, wie viel Speicher es belegt, und geladene Modelle bekommen einen grünen Punkt.

Rechtsklick auf ein lokales LLM für Starten, Stoppen, Start beim Anmelden und GPU-Speicher freigeben: Seine Modelle werden entladen, es läuft weiter und lädt wieder eines, wenn es gefragt wird.

Wenn der letzte Agent, der ein lokales LLM genutzt hat, beendet wird und das LLM seine Modelle noch hält, fragt eine Meldung, ob der Speicher zurückgegeben werden soll: Freigeben entlädt sie, Behalten lässt sie geladen.

Ein lokales LLM, das GPU-Speicher belegt, bekommt an seinem Feld einen roten Stoppknopf. Er fragt zuerst: GPU-Speicher freigeben entlädt seine Modelle; Stoppen beendet es. Bei LM Studio heißt der Knopf Server stoppen: Nur sein Server endet, die App bleibt mit geladenen Modellen offen. Ein Modell, das ein lokales LLM geladen hat, das aber kein Agent nutzt, ist durch eine durchgehende helle Linie mit ihm verbunden.

LM Studio kann ohne seinen Server geöffnet sein. Sein Feld zeigt dann Server aus mit einem gelben Punkt, Agenten erreichen es nicht, und sein Menü bietet Server starten (lms server start).

Modelle gleichzeitig

llama.cpp, LM Studio und Ollama können mehr als ein Modell geladen halten. Verbindest du Agenten mit verschiedenen Modellen eines lokalen LLMs, stellt die App ein, wie viele es gleichzeitig geladen hält — so viele, wie seine Agenten nutzen —, mit derselben Vorschau, Sicherung und Rückgängig wie die Verbindung, und bietet einen Neustart an, wenn es läuft, denn es liest die Zahl beim Start. Wo diese Zahl nicht Sache der App ist (eine Systeminstallation oder dein eigener Startbefehl), sagt ein Hinweis, wo sie eingestellt wird.

Passen die Modelle zusammen nicht in den Speicher der GPU, sagt eine Warnung das: Das lokale LLM wechselt sie dann aus, was langsam ist, oder ein Teil eines Modells läuft auf dem Prozessor. Der Start eines Agenten prüft dasselbe: Braucht das Laden seines Modells mehr GPU-Speicher, als frei ist, wirst du vorher gefragt, mit dem, was den Speicher gerade belegt — GPU-Speicher freigeben, dann starten, Trotzdem starten oder Abbrechen.

In AI Agents Map schaut die App nach einer übernommenen Änderung des lokalen LLMs oder Modells eines Agenten, wie viele verschiedene Modelle die Agenten jedes lokalen LLMs jetzt nutzen. Wo sie die Zahl setzen darf — die Einstellungsdateien von llama.cpp und Ollama in den App-eigenen Installationen, die Einstellung „eins oder viele“ von LM Studio —, zeigt eine zweite Vorschau die Änderung mit ihrer Bedeutung und etwaigen Warnungen; Übernehmen schreibt sie mit einer Sicherung, und Rückgängig nimmt sie zurück. Eine Zahl, die du in deinem eigenen Startskript festgelegt hast, bleibt, wie sie ist. Sind es mehr Modelle, als geladen bleiben, oder zusammen zu groß für die Grafikkarte, sagt das auch der Status der Spalte Anbieter.

  • Im Hintergrund blendet das Feld aus; der Lauf geht weiter, und eine Meldung sagt, wann er fertig ist.
  • Abbrechen beendet den Agenten sofort (sein Programm und alles, was es gestartet hat).
  • Schlägt er fehl, bleibt das Feld mit dem, was schiefging, stehen, bis du es schließt; der Text lässt sich markieren und kopieren.

Nachschlagen im Web (Modellberatung, MCP-Updates) läuft mit dem Web und sonst nichts: ohne die MCP-Server, Connectors, Plugins und Hooks des Agenten.

Der lokale Helfer

Ein Agent, der mit einem lokalen LLM verbunden ist, kann KI-Hilfe mit einem der Modelle dieses LLMs beantworten: auf diesem PC, ohne Web, ohne Tokens eines Plans und ohne dass etwas den Computer verlässt. Er beantwortet, was kein Web braucht: die Zusammenfassung von Smart Check, welcher MCP-Server passt, und die Tipps auf der Karte Leistung eines lokalen LLMs. Modellberatung und MCP-Server-Updates gehen weiterhin an den Online-Agenten, da sie das Web brauchen.

Die App schlägt einen vor — das größte Chat-Modell, das deine Grafikkarte fasst (Audio-, Embedding- und Tokenizer-Modelle bleiben außen vor) — auf Smart Check, mit Verwenden. Einstellungen › KI-Funktionen › Lokaler Helfer listet jeden Agenten und jedes Modell, das es sein kann, den vorgeschlagenen zuerst, und Aus. Nichts wird genutzt, bevor du es wählst. Bevor er antwortet, startet die App das lokale LLM und lädt das Modell (ein Schritt im Fortschrittsfeld). Der Helfer läuft ohne Werkzeuge, ohne MCP-Server, ohne Erweiterungen und ohne Projektdateien. Jeder Agent, dessen Add-on sagt, wie man ihm offline eine Frage stellt, kann der Helfer sein; Pi ist der erste.

KI-Prüfungen und der lokale Helfer

In AI Agents Map stehen unter Einstellungen › KI-Funktionen die Tägliche KI-Prüfungen (standardmäßig aus) und darunter das Ergebnis der letzten Prüfung mit Jetzt prüfen, das sofort fragt, auch wenn die täglichen Prüfungen aus sind. Die Prüfung läuft beim Öffnen des Fensters im Hintergrund und wird jede Stunde angesehen; der Agent für KI-Prüfungen wird höchstens einmal am Tag gefragt (nach einer fehlgeschlagenen Suche wieder nach sechs Stunden). Was er findet, steht im Status der MCP-Spalte: Release-Seite öffnet die Veröffentlichung im Browser, Mit … erledigen zeigt zuerst die Aufgabe so, wie sie gesendet wird, und startet sie erst nach Fortsetzen in einem Terminal-Tab, und Verwenden… öffnet das auf diesem PC Gefundene, wenn die neuere Version schon da ist. Geprüft werden nur Server, deren Version die App erkennen kann (siehe Gefundene Updates); andere Server werden nicht gesendet.

Der lokale Helfer wird unter Einstellungen › KI-Funktionen › Lokaler Helfer gewählt; der Vorschlag für deine Grafikkarte ist mit (empfohlen) markiert. Ist er gewählt, wird er auf der Karte Leistung eines lokalen LLMs unter Fragen zuerst angeboten.

Protokoll

Jeder Lauf der KI-Hilfe wird aufbewahrt, damit du — oder jemand, der sich mit dem Setup gut auskennt — nachsehen kannst, was getan wurde. Jeder Eintrag zeigt, wann er lief, Agent und Modell, das Ergebnis (erfolgreich, fehlgeschlagen, abgebrochen), die Zeit und die Tokens. Geöffnet zeigt er den ganzen Text: die Optionen, mit denen der Agent eingeschlossen wurde, die Schritte, jede Frage genau so, wie sie gesendet wurde, mit der Antwort des Agenten, was die App aufgrund der Antwort geändert hat (mit der Sicherung, für Rückgängig von Hand) und, bei einer Aufgabe in einem Terminal-Tab, was das Terminal am Ende zeigte. Das Risiko steuern

Die Risikostufe ist der ernsteste Punkt, den die Karte findet:

  • Hohes Risiko — er kann ernste Dinge tun, ohne zu fragen: jeden Befehl ausführen oder ohne Sandbox und ohne Rückfragen arbeiten. In Ordnung in einem Wegwerf-Container oder einer virtuellen Maschine; auf deinem eigenen PC lass ihn zuerst fragen.
  • Mittleres Risiko — manches geschieht ohne Frage, etwa das Bearbeiten von Dateien im Projekt, oder eine automatische Prüfung entscheidet für dich.
  • Geringes Risiko — er fragt vor allem, was zählt, oder kann es gar nicht.

Gute Gewohnheiten, egal welche Einstellungen:

  • Bei Befehlen zuerst fragen auf deinem eigenen Computer; einzelne, harmlose Befehle (etwa git status) mit einer Erlauben-Regel freigeben statt die ganze Shell.
  • Die Sandbox einschalten, wo der Agent eine hat (Claude Code, Codex, Cursor CLI), und das Netzwerk darin aus lassen, solange keine Aufgabe es braucht.
  • Agenten im Projektordner starten, nicht in deinem persönlichen Ordner, und Schlüssel und Passwörter davon fernhalten.
  • Wenige MCP-Server: nur die, die du nutzt und denen du vertraust. Jeder läuft mit deinen Rechten.
  • Unbeaufsichtigte Arbeit (Umgehungsmodus, „YOLO“, Pi mit allen Werkzeugen) in einem Container oder einer virtuellen Maschine laufen lassen.
  • Lokale LLMs auf 127.0.0.1: Ihre Server haben kein Passwort.

Vorsicht Eine automatische Prüfung (der Modus auto von Claude Code, assisted von Copilot, auto-review von Cursor, smart von Hermes) ist eine zweite KI, die jeden Schritt beurteilt. Sie spart Rückfragen, aber sie ist ein Urteil, keine Mauer.

Die Begriffe erklärt

Was eine Sandbox ändert: Befehle erreichen nur den Projektordner und was du erlaubst.

Sandbox
Ein abgeschirmter Bereich, in dem die Befehle des Agenten laufen. Darin kann ein Befehl nur den Projektordner berühren (und was du erlaubst) — nicht den Rest deines persönlichen Ordners, deine SSH-Schlüssel oder Browserdaten und oft nicht das Internet. Ohne Sandbox kann ein Befehl des Agenten alles, was du kannst.
Freigabe (zuerst fragen)
Bevor der Agent eine Datei bearbeitet oder einen Befehl ausführt, zeigt er, was er tun will, und wartet auf Ja oder Nein. Je weniger er ohne Frage darf, desto mehr Kontrolle behältst du — und desto öfter wirst du gefragt.
Erlauben- und Verbieten-Regeln
Listen von Befehlen oder Werkzeugen, die der Agent ohne Frage nutzen darf (erlauben) oder nie (verbieten). Verbieten gewinnt gegen Erlauben. Eine Regel, die jeden Shell-Befehl erlaubt, schaltet die Freigabe für die Shell aus.
Vertrauenswürdiger Ordner
Ein Ordner, in dem der Agent laut dir arbeiten darf. Dort nutzt er auch die eigenen Anweisungen und Einstellungen des Ordners, die von jemand anderem stammen können, wenn du ein Projekt klonst.
Netzwerkzugriff
Ob Befehle das Internet erreichen dürfen. Code, der deine Dateien liest und Daten verschicken kann, könnte sie preisgeben; auch das Installieren von Paketen braucht das Netzwerk.
Umgehung („YOLO“)
Alles ohne Frage und ohne Grenzen. Nur für eine Wegwerf-VM oder einen Container.
Automatische Prüfung
Ein zweites KI-Modell lässt harmlose Aktionen durch und fragt beim Rest nach.
Prompt Injection
Anweisungen, versteckt in einer Webseite, Datei oder Werkzeugantwort, die den Agenten zu etwas bringen wollen, worum du nicht gebeten hast. Zuerst fragen, eine Sandbox und kein Netzwerk stoppen sie.
Geheimnisse verbergen
Text, der wie ein Passwort, Token oder Schlüssel aussieht, wird maskiert, bevor das Modell ihn sieht oder er in einem Log landet.
Werkzeuge
Was der Agent überhaupt kann: lesen, schreiben, Befehle ausführen, im Web suchen. Ein Werkzeug, das er nicht hat, kann nicht missbraucht werden.
MCP-Server
Ein kleines Programm, das dem Agenten zusätzliche Werkzeuge gibt. Es läuft als du, mit deinen Rechten.
127.0.0.1 (localhost)
Eine Adresse, die nur Programme auf diesem PC erreichen. Ein Server auf 0.0.0.0 ist von jedem Gerät in deinem Netzwerk erreichbar.

Add-ons

Alles, was AI Agents Map über einen Agenten oder einen LLM-Anbieter versteht, ist ein Adapter: wie er gefunden und installiert wird, seine Sitzungen, Sicherheitseinstellungen, MCP-Server und Skills. In AI Agents Map ist jeder Adapter ein Add-on: Die Pakete bringen alle mit, signiert und ausgeschaltet, und du schaltest die ein, die du nutzt. Add-ons bringen auch neue Agenten, neue Anbieter und Funktionen über die Zahlen hinaus, etwa Insights (Sitzungsthemen und eine Zusammenfassung von Claude). Das Plugin AI Agents Map hat die Adapter eingebaut und keine Add-ons.

AI Agents Map einrichten

Ein neues AI Agents Map öffnet sich auf seiner Willkommensseite. Jeder Agent und jedes lokale LLM, das AI Agents Map kennt, ist eine Karte mit eigenem Symbol, in drei Gruppen: KI-Agenten, Lokale LLMs und Online-Anbieter (die Namen von Anthropic, OpenAI und den anderen auf der Karte). Jede Karte sagt, ob das Programm hier ist:

  • Installiert (grün) — so gefunden, wie die Karte es findet; die Karte ist schon angehakt;
  • Früher benutzt — jetzt nicht installiert, aber seine Einstellungen sind noch da;
  • Nicht installiert — hake es an, um es danach über seine Karte zu installieren.

Die Willkommensseite: gefundene Programme stehen zuerst und sind angehakt.

Klicke eine Karte an (oder drücke darauf Leertaste), um sie an- oder abzuhaken; eine angehakte Karte hat einen blauen Rahmen und ein Häkchen. Einschalten (mit der Zahl der angehakten Karten) lädt sie und zeigt die Karte; hast du Programme angehakt, die nicht installiert sind, öffnet sich Setup: ⋯ auf ihren Karten › Installieren…. Später startet mit einer leeren Karte. Solange nichts eingeschaltet ist, öffnet sich AI Agents Map bei jedem Start wieder auf der Willkommensseite. Danach sind dieselben Karten im Setup (dem Knopf in der Kopfzeile), wo Agenten und Anbieter jederzeit ein- und ausgeschaltet werden.

Bei jedem späteren Start sieht AI Agents Map wieder nach, was installiert ist, und schaltet das Add-on jedes gefundenen Agenten, lokalen LLMs und Online-Anbieters von selbst ein, damit alle auf der Karte stehen. Eines, das du selbst ausgeschaltet hast (hier, auf der Add-on-Seite oder auf der Willkommensseite nicht angehakt), bleibt aus; schalte es wieder ein, um es zurückzubekommen.

Die Add-on-Seite

Öffne sie mit dem Puzzle-Knopf in der Kopfzeile, über Einstellungen › Add-ons oder über jeden Hinweis „Add-on verfügbar“. Sie zeigt in zuklappbaren Gruppenkarten, die offen beginnen:

  • Vorschläge für diesen PC — ein Add-on, dessen Agent oder Anbieter hier installiert ist, aber noch nicht gezeigt wird;
  • Installierte Add-ons — an, aus oder nicht geladen mit dem Grund (zum Beispiel eine geänderte Datei); Agenten und Anbieter durch eine Linie getrennt;
  • Verfügbar — die übrigen Add-ons des Katalogs;
  • In AI Agents Map eingebaut — Agenten und Anbieter, die kein installiertes Add-on mitbringt (wenn du AI Agents Map aus seinem Quellordner ohne Add-ons startest).

Installierte Add-ons: an oder aus, mit Installieren und Deinstallieren für das Programm.

Die Karte eines eingeschalteten Agenten oder lokalen LLMs hat Installieren und Deinstallieren für das Programm selbst (das jeweils nicht zutreffende ist ausgegraut), und jede Karte mit einer Homepage hat einen Globus-Knopf, der sie in deinem Browser öffnet.

Die Suche findet Namen, Beschreibungen und was ein Add-on liest; die Filter darüber beschränken die Liste auf Agenten, Anbieter, Funktionen, die installierten oder die mit Update. Klicke eine Karte an für ihre Details: was es liest, was es sendet, was es darf und seine Datenschutzstufe.

Installieren, ein- und ausschalten, aktualisieren, entfernen

Installieren (oder Add-on holen) zeigt zuerst, was das Add-on liest, sendet und darf; erst nach deinem OK wird es heruntergeladen, geprüft und eingeschaltet. Ausschalten und Einschalten wirken sofort, ohne Neustart: Seine Agenten, Anbieter, Abschnitte und Karten erscheinen oder verschwinden überall. Aktualisieren ersetzt es durch die neuere Version aus dem Katalog, nachdem die neue geprüft wurde; Entfernen verschiebt es in den Papierkorb. Aus Datei installieren… nimmt ein Add-on-Zip, das du selbst heruntergeladen hast; es gelten dieselben Prüfungen.

Hat der Katalog neuere Versionen installierter Add-ons, steht auf den Karten in Setup Add-on-Update, der Spaltenstatus nennt Add-on-Updates bereit mit Alle aktualisieren und Add-ons, und die Add-ons-Seite zeigt eine Leiste mit Alle aktualisieren. Das ⋯-Menü der Karte (oder ein Rechtsklick auf sie) hat außerdem Add-on auf Version aktualisieren, für dieses eine Add-on. Alle aktualisieren bringt eines nach dem anderen auf den neuen Stand, mit denselben Prüfungen, und sagt in einer Meldung, welche aktualisiert wurden. Es läuft immer nur eine Installation oder Aktualisierung; eine weitere, die währenddessen gestartet wird, bittet, es gleich noch einmal zu versuchen.

Nur vom Autor. AI Agents Map lädt nur Add-ons, die von Uwe Bruckhaus signiert sind (Schlüssel-Fingerabdruck SHA256:e5cC634Ke3Our5LAeSc88qs22NKZEHTncBW5Ig3amWQ). Bevor irgendetwas eines Add-ons läuft, wird die Signatur mit OpenSSHs ssh-keygen geprüft, jede Datei mit ihrer SHA-256-Prüfsumme verglichen, und keine Datei darf hinzugekommen sein. Ein Download muss außerdem zur SHA-256-Prüfsumme im signierten Katalog passen.

Ein Add-on erstellen

Ein neues lokales LLM oder ein neuer Agent braucht nichts als ein Add-on: AI Agents Map baut seine Karte, seinen Kasten und seine Linien auf der Karte, seine Details, die Modelle-Seite und die Sicherheitsseite aus dem, was das Add-on darüber sagt. Wenn du ein wenig programmieren kannst, fang mit den Vorlagen im AI Agents Map-Repository an (templates/, erklärt in docs/addons.md): eine Datei für ein lokales LLM, eine Datei mit Fakten für einen Agenten. Schick das Add-on an github.com/uBruckhaus/asterism-addons; ist es geprüft und signiert, erscheint es für alle unter Verfügbar.

Datenschutz und Sicherheit

  • Keine Administratorrechte für die App. Sie läuft nie als root und sieht nie ein Passwort. Einen Agenten, der als Systempaket kommt (etwa Hermes oder OpenClaw), installiert die Paketverwaltung des Systems mit sudo in einem Terminal, das du siehst, nachdem dir der Befehl gezeigt wurde.
  • Keine Zugangsdaten gelesen. Sie liest die Einstellungen der Agenten, aber nie ihre Zugangsdateien. Ob ein Agent angemeldet ist, wird daran erkannt, ob eine solche Datei existiert. Werte von Schlüsseln und Headern werden nie gezeigt.
  • Keine Gespräche gelesen. Nutzungszahlen werden nur als Zahlen und Zeiten gelesen. Die einzige Ausnahme ist das Mitlesen einer Instanz Im Hintergrund (Terminals…), auf deinen Klick und nur für diese Instanz; nichts davon wird gespeichert.
  • Netzwerk nur auf Wunsch — Modelle, MCP-Server oder Skills suchen, installieren, einen Server testen —, dazu alle paar Stunden eine Update-Prüfung.
  • Geprüfte Downloads. Programme werden nur installiert, wenn der Download zur Prüfsumme passt, die sein Release veröffentlicht.
  • Vorschau und Rückgängig. Jede Änderung an den Einstellungen eines anderen Programms wird vorab gezeigt, gesichert und lässt sich rückgängig machen. Einstellungen, die Schlüssel enthalten können, werden nur für dich lesbar geschrieben.
  • Begrenzt. Jedes Programm läuft ohne Shell, und jede Antwort wird mit Größen- und Zeitgrenze gelesen.
  • KI-Funktionen nur, wenn du sie wählst. Das Nachschlagen von Smart Check läuft auf Klick, die täglichen KI-Prüfungen nur, wenn sie eingeschaltet sind. Der Agent bekommt eine kurze Zusammenfassung (Namen, Versionen, Modelle), nie Schlüssel oder Einstellungswerte, übergeben so, dass andere Benutzer des Computers sie nicht lesen können; seine Antworten werden geprüft, bevor sie gezeigt werden, und nie ausgeführt. Aufgaben laufen in einem Terminal, das du siehst, und der Agent fragt vor jedem Schritt. Du nutzt sie auf eigene Gefahr.

Die README in jedem Repository listet vollständig auf, was gelesen, gestartet und geschrieben wird.
