About this manual

This manual describes AI Agents Map, a plugin for the Omarchy desktop: a button in the bar opens it. It uses the Omarchy theme's colours (or GNOME's Adwaita look) and keeps its settings in ~/.config/omarchy/ai-agents-map/.

Contents

Introduction

AI Agents Map shows the AI setup on your computer as cards and as a map: which coding agents are installed, which language models they use — cloud services and local runtimes — the models those serve, and which MCP servers and skills each agent has. And it lets you change that setup by drawing lines.

The main window: the map across the whole width, the GPU card above it, the ! for open problems in the header.

What it does

  • Coding agents — Claude Code, Codex, GitHub Copilot, Cursor CLI, Gemini, OpenCode, Pi, Hermes and more: their version, plan, limits and usage, and what each one still needs, with the command that fixes it.
  • Local LLMs — llama.cpp, Ollama, LM Studio, vLLM, Jan, KoboldCpp and Strata: install them, download models, set the context size that fits your graphics card, and start them together with the agents that use them.
  • MCP servers and skills — found on your computer or on the web, with recommended servers and a search of the official MCP registry.
  • Column status — a symbol on each column's Ask AI bar, each problem with the way to where it is fixed; what your setup is good for is on the welcome page and in Help.

Key ideas

Agent
A program you talk to that writes code or does tasks, such as Claude Code.
LLM provider
Where an agent's model runs: a cloud service (Anthropic, OpenAI, …) or a local LLM runtime on this computer (llama.cpp, Ollama, …).
Model
The language model itself. Local models are files, usually in GGUF format.
MCP server
A small program or web service that gives agents extra tools — reading files, searching the web, controlling a browser. MCP is the Model Context Protocol.
Skill
A folder with instructions (a SKILL.md) and sometimes scripts that teach an agent how to do a particular job.

Nothing changes without a preview

Every change to an agent's settings is shown first, line by line, before anything is written. The old file is kept as a backup, and the bar that appears after the change has Undo. The app itself never runs with administrator rights; only installing an agent that comes as a system package asks for your password, in a terminal you watch.

Installation

Installing the plugin

Install AI Agents Map from the Omarchy Plugin Marketplace, or from a terminal:

omarchy plugin add https://github.com/uBruckhaus/omarchy-ai-agents-map.git --enable

A robot button appears in the bar. Everything else it needs comes with a standard Omarchy install, its signed add-ons included. To run agents inside the window, install VTE: sudo pacman -S vte4. Optional: mise installs and updates agents.

First start

A fresh install opens on the welcome page: the agents and local LLMs installed on this computer are cards that are already ticked, and Switch on puts them on the map (see Setting up AI Agents Map). After an update from an earlier version of the plugin, your settings stay, and the add-ons of the agents and local LLMs on this computer are switched on by themselves, so the map shows what it showed before.

The bar button opens the window, brings it to the front, or hides it when it is already in front. Closing the window hides it; the program keeps running in the background so it opens again at once. Settings › In the app launcher adds an entry to Omarchy's app launcher.

Note While an agent runs inside the window, closing it asks first: Stop and close (the agent's local LLM then stops too and frees the graphics card's memory) or Keep running.

While the app looks at what is on this computer on the first open, an animated overlay lists what it finds, kind by kind: agents, local LLMs, MCP servers and skills, each with a spinner that turns into ✓ and a number, and how many of them are not connected yet. It fades out by itself after a moment; a click closes it at once.

Removing the plugin

omarchy plugin remove ubruckhaus.ai-agents-map.

Before removing, switch off Settings › Start local LLMs with their agents so the background watcher is removed too, and Settings › In the app launcher to delete the launcher entry. Changes you made with the app stay: agents' settings, MCP servers, skills and installed local LLMs. Uninstall a local LLM first (right-click › Uninstall…) if you want it gone. To delete the app's own state as well:

rm -rf ~/.config/omarchy/ai-agents-map ~/.local/state/ai-agents-map \
       ~/.cache/ai-agents-map ~/.local/share/ai-agents-map/addons

Choosing what the map shows

The map shows everything that is set up. The MCP servers, Agents, Providers and Models filter buttons above the map (and Settings › Map) leave whole columns out of it and are remembered.

In a small window (up to 55 % of the screen, or below 1150 pixels) the map shows Agents and Providers; in a medium window (up to 80 % of the screen, or below 1600 pixels) it adds Models; in a larger window all four columns show. A column the view leaves out can still be turned on with its button above the map, and the map rearranges to fit it; the filter hides columns in every view. The shown columns are centred and adjust their width (266 to 560 pixels) and gap to the free space, and the map fits the window's width until you zoom (Ctrl+0 fits it again).

Working with the map

An agent’s model is a chain: one line from the agent to its provider, one from the provider to the model it uses. Models nobody uses stay boxes without a line, and a card’s filter (only what is connected or pinned) hides them. Drawing a local provider onto one of its models is one short step: the provider uses that model, and an agent you connect to the provider later gets it. If a drop cannot work, a short note says why, for example which provider the agent must be connected to first. A simple drawn connection or disconnection asks for Apply in a small dialog, then a short note confirms it, with Undo; an error says what went wrong. Changes requiring further steps use the detailed review. When one agent calls another, the called agent’s active path and the arrow between them use a separate collaboration colour, including deeper calls. The arrow points to the agent that is used; once the work is done, it stays dim. The tree symbol on an agent card opens its recent subagents; it is bright while one works and dim when only finished ones remain.

Ask AI can propose the same map edits, including switching an existing model, connecting an existing skill folder, repairing a failed connection and signing an agent in or out. It shows the same preview and asks before applying. For local LLM speed, GPU memory, context size, Vulkan or ROCm questions, Ask AI opens Performance, which uses this PC’s hardware and measurements before suggesting a change.

Below the question, a scrollable card suggests requests for MCP servers and skills, agents, providers and models. Choosing one fills the question with its category at the start (for example, Models:) and switches to that category; it does not send anything. You can edit the question or type a category yourself. Only Ask sends it. The status view still lets you inspect each category’s findings.

You can shape these suggestions: the bookmark button in the question field keeps what you typed as a new suggestion of the chosen category (up to 12 per category), the pencil next to a suggestion edits it in place (Enter keeps it, Esc cancels, an empty text removes it), its × removes it, and the arrow at the end of the line brings back the built-in suggestions.

Column status

Every column's Ask AI… bar shows that column's state at its left, and the header shows the worst state of all columns, also of a hidden one: a green check mark when all is fine, a yellow triangle for tips, updates or suggestions, a red ! when something needs fixing. A click on the symbol opens the column's list, worst first: an agent not signed in, a local LLM without models, a connection that does not work, little free space for models, each with a button to where it is fixed. Ask AI on a line puts it into the prompt; only Ask sends it. A click on the header's symbol goes to the first column concerned. The check only reads; it never changes, starts or sends anything.

The list also shows new programs or skills found on this PC, what is on this PC but not on the map, and updates for installed agents, local LLMs and MCP servers, each with its button. Updates are checked in the background when the window opens, at most every six hours. An update starts only when you click Update (see Updates found). What your setup is good for is on the welcome page and in Help, under What you can do with it.

Smart cards on the map

A collapsed Ask AI… bar sits at the top of every map column, with a status symbol at its left: a green check mark when all is fine, a yellow triangle for tips, updates or suggestions, or a red ! when something in that column needs fixing. The header bar shows the overall status across all four columns (even hidden ones) and opens the first column that needs attention. Clicking a column’s status symbol opens its status list: each finding for that column with the button that opens where it is fixed and Ask AI to pre-fill the prompt, newer versions of installed agents and local LLMs (Update runs mise upgrade or the agent’s own updater in a terminal, or opens the install review; checked at most every six hours), MCP server updates from the daily AI checks, and Check again. On the welcome page, What you can do with it shows the use cases (everyday help, vibe coding, images, voice, research and writing) as Ready, Almost or Not yet, with what is there for each and the next step.

The app reads the signed add-on catalog in the background at start: from its cache, and online only when Look for add-ons online is on. Each column’s status list then also shows agents and local LLMs on this PC whose add-on is switched off or not installed yet (Get add-ons or Add-ons opens the add-ons to switch on or get), new programs or skills found on this PC (Add MCP server…, Add skills…), and installed add-ons with a newer version in the catalog. Update all shows them with their versions and, once confirmed, updates them one after the other, each checked against the catalog; one message says what was updated and what was not.

Clicking the Ask AI… part of the bar opens the prompt in a centred window over the map, with the helper and its cost in the header and the buttons in the footer (or offers Get started when no AI helper is set up yet). Before anything is sent, the card shows which helper answers (with a menu when more than one is ready) and whether it runs locally (Local, no tokens) or Uses plan/tokens; only clicking Ask sends your one-line request. The helper either asks one clarifying question, offers to move the request to the right column, or proposes checked candidates from real search results. In the Models column, the card shows this PC’s VRAM, RAM and free disk space and marks each candidate as Fits in VRAM, Uses RAM offload or Too large for this PC. Review opens the download preview before anything is downloaded or changed, and once a model is ready you can optionally connect it to an agent through the connection preview with Undo.

In the MCP servers and skills column the helper can add an MCP server from the official registry, connect a server to an agent, or disconnect it. It can disconnect several or all servers in one step, with one preview and one Undo. You choose the agents, fill in what the server needs (keys stay on this PC and never reach the helper), and approve the normal review; then the change is made and the map shows it. It turns down anything else and names the right column. It can also disconnect skill folders in the same step. It cannot add or update skills yet, update programs, or delete a server from the PC.

In the Models column the helper can also remove a model of a local LLM: you see the normal removal review first, and files go to Trash where that is possible. It can also move a model folder to another disk, with a preview and Undo in the header. Each folder gets its own review. It can also disconnect agents from one, several or all models of a local LLM, in one preview with one Undo; no file is deleted.

In the Agents column the helper can install, update or remove an agent, where the Agents page offers that. You see its normal review; the step then runs in a terminal you can watch. It does not start agents or change their settings.

In the Providers column the helper can install or update a local LLM, and start or stop it, where the app offers that; the app's normal review opens for the step. It cannot uninstall a provider or sign in to an online one.

Ask AI also offers the other steps of the app’s menus, each through the same menu with its own review and Undo. In the Agents column: the test question, the API key card (you type the key there; the helper never sees it), security settings, starting an agent or stopping one that runs outside the app, its connections and details, and an add-on’s details, switching it on or off, installing, updating or removing it. In the Providers column: the same add-on steps for local LLMs, and Find existing AI, which looks for programs and model folders already on this PC; the app does not uninstall a local LLM program itself. In the Models column: loading, unloading or importing a model, and the model a local LLM uses itself, checked by the same rules as a model switch and with its own Undo, as when you draw it on the map. In the MCP servers and skills column: what Found on this PC shows. Connecting an agent to an online provider signs it in to its own provider; another agent’s provider is refused with the reason. When agents leave a local LLM, only their configuration changes, as when you take the line away. After a download, Ask AI offers the agents that can use a local LLM, and the model becomes that agent’s model, as when you draw the connection.

When a column cannot do something but the web can tell how, an online helper searches the web and the card shows its answer with sources; a local helper cannot search the web and says so. After such an answer, Do it with … shows the prompt, and the agent then works in a terminal and asks before each step that changes files. The task itself waits in a private file in AI Agents Map’s cache; the agent’s command line only names that file, so other accounts on this PC cannot read it.

At the top, one line says whether the agent is ready (and if not, why) and whether it is running now or when it was last used. Below it, every category is a card that folds: click its heading to open or close it. They start folded, each with a one-line summary and badges; a category you open stays open on the next details pages.

Projects are shown for every agent whose sessions the app reads — Claude Code, Codex, Pi, Oh My Pi, OpenCode, Hermes, DeepSeek Harness, Goose, Gemini CLI and OpenClaw: working time, sessions, tokens, subagent runs, lines changed and what the tokens would cost at API prices. The numbers come from each agent's own session files or database; no text is read.

API cost. The amounts are an estimate: the token counts the agent keeps (input, output, cache read and cache write, per model) at the providers' published API prices — Anthropic, OpenAI, DeepSeek, xAI and Google, with the date they were taken. A session counts on the day of its last reply; local models cost nothing. Crush keeps no token counts that add up, so its card shows the cost Crush itself reports. For an agent that keeps no token counts on the PC (Cursor CLI, Antigravity, Muse) the card says the cost is not known; its provider's account page has it. Amounts are shown in US dollars, or in euros at the European Central Bank's daily rate (Settings › Costs).

With the Insights add-on (see Add-ons) the Topics card shows first which topics took the most tokens in the last 30 days (Most tokens: sessions with the same title are one topic, each with its share of all tokens), then the titles the agent gave its sessions itself, per project (By project), and offers Summarize with Claude… (when Claude Code is installed). Its tokens come from the agent's own session files without cache reads, so they can be far lower than in Usage and tokens, which may count cache reads. Before anything is sent, you see exactly what will be sent: the titles and numbers, never the conversations.

Starting and stopping agents

The last 50 project folders are kept per agent.

Each agent’s Start submenu has three sections separated by lines: Start with the current folder, Choose folder…, and a searchable Recent projects drop-down. The drop-down scrolls and lists all folders used to start this agent from the map, newest first. Choose a past project, then Start. Choosing a folder in the folder picker starts one session there. No pinned folder is required: without one, Start uses Settings › Agents start in, or your home folder. The agent’s details page has a scrollable Recent projects card with every recorded folder. Click a row to open Start with that folder selected. Its pin sets this agent’s next default; only one folder per agent can be pinned, and unpinning restores the general default. The trash button removes the entry and its pin from this agent’s history, never the folder or its files. The same submenu, history and pins apply to Start here and Start in terminal. Start again offers the submenu again. Running sessions keep their existing folder; cancelled choices and failed launches add no history.

  • ▶ on the agent's box, or Start here in its menu, runs the agent in a terminal inside the window, in place of the map. This needs VTE (vte4).
  • Start in terminal opens it in a terminal window of its own.
  • While it runs inside the window: Show terminal and Stop. Stop ends the agent and everything it started, such as its MCP servers.
  • Terminals… lists where else the agent runs: Here, in this window, each Terminal window (a click brings it to the front) and each instance In the background — one with no window, such as claude -p … run by a script or by another agent. A click on a background instance opens a terminal tab that shows what it writes, as it writes it: questions, answers and the tools it uses (from its session file, or its output when that goes to a file). The tab ends when the instance ends. This is the one place where the app shows conversation text, and only for the instance you click.
  • Stop… — also the small stop button left of ▶ on the agent's box — stops one of its instances outside this window. Pick it from the list, which says where and when each one was started. It is asked to end (SIGTERM) and, if it is still there after 3 seconds, ended. Only that very process is stopped: if it has ended in the meantime and its process number now belongs to another program, nothing happens.

When agents have terminals in the window, a tab line above the map shows one tab per terminal with a dot for working, running or ended. Click a tab to show that terminal; × closes an ended one.

An agent with an open instance anywhere on the computer gets a green dot and running, and the model box it runs with says in use · <agent>.

Network traffic

A running agent's box and card show what it receives and sends (↓ in, ↑ out). Click that line, or ⇅ in the header for all running agents, to open its network page: Now, The last 5 minutes as a chart (in green, out blue), Where it goes — online APIs, local LLMs, this PC and your local network, each with its share — and Programs: the agent itself and the programs started by it, such as its MCP servers. It is counted from the agent's own TCP connections while the app is open (no administrator rights needed; UDP is not counted) and stays on this PC.

Subagents

Claude Code and OpenCode can hand parts of a task to subagents. While one of an agent's subagents works, its box on the map shows a small tree mark next to ⇅; while it has only finished ones listed, the mark is dimmed. Click the mark to open the agent's Subagents page: a map of its own, laid out like the big one, with the agent's card at the left and a Subagents card at the right. Each box shows the subagent's task, its type, the folder its session works in, and working or done … minutes ago. Light runs on the lines to the working ones; finished ones are dimmed. Hover a box to read its whole task.

Starting and stopping with agents

Connect an agent to a local LLM once, then just start the agent — even with the app closed or after a reboot. Its local LLM starts with it, and when the last agent using it closes, the LLM stops about five seconds later, so its graphics memory is free again.

A small background service, ai-agents-map-providers.service, does this. It is set up with the first connection to a local LLM and removed when the last one goes, or when you switch off Settings › Start local LLMs with their agents.

Note KoboldCpp takes a few seconds to start, longer than some agents wait. So it starts at login, and when the last agent closes only its model is unloaded.

Note Strata is not started with its agents. Start it on the map (the ▶ button on its box) or in Strata itself before you work with an agent connected to it.

Strata

Strata is a local inference engine with a terminal app of its own. It serves one model at a time on 127.0.0.1:8080 and speaks the OpenAI and Anthropic APIs, so agents connect to it like to the other local LLMs. AI Agents Map finds it by its own strata command (another program with that name, such as the Strata file manager in /usr/bin, is not taken for it), by its running server, and by its models: the run configs Strata keeps in ~/.local/share/strata/install.

Choosing, downloading and tuning a model happens in Strata’s own screens: run ~/.local/bin/strata launch in a terminal (~/.local/bin/strata launch --status shows what is serving). Once Strata has started a model this way, it remembers it as a launch preset. From then on Start on the map (the ▶ button on Strata’s box) starts the preset used last (strata launch --preset … --no-tui, which returns when the model serves; large models take a few minutes), and Stop stops it (strata launch --stop).

Strata and llama.cpp both use port 8080 unless told otherwise. An agent connected from the map names its local LLM (strata-local), so it stays Strata’s even when llama.cpp uses that port too; only one of them can serve on a port at a time.

AI Agents Map does not remove Strata. To remove it yourself, delete its terminal (~/.local/share/strata/terminal) and the link ~/.local/bin/strata. Its engines and run configs are in ~/.local/share/strata (components, install), its models in the folders you chose in Strata, and the desktop app’s chats in ~/.strata; delete those only if you no longer want them.

Models at once

llama.cpp, LM Studio and Ollama can keep more than one model loaded. When you connect agents to different models of one local LLM, the app sets how many it keeps loaded at once to the number its agents use — with the same preview, backup and Undo as the connection — and offers to restart it if it is running, because it reads the number when it starts. Where that number is not the app's to change (a system install, or your own start command), a note says where to set it.

When the models together do not fit in the GPU's memory, a warning says so: the local LLM then swaps them, which is slow, or part of a model runs on the processor. Where it may set the number — llama.cpp’s and Ollama’s settings files of the app’s own installs, LM Studio’s one-or-many setting — a second Preview shows the change, with what it means and any warning; Apply writes it with a backup, and Undo takes it back. A number fixed in your own start script is left as it is. When the models are too many for what is kept loaded, or too big together for the graphics card, the status of the Providers column says so as well.

Local connections

Open Connections, then Add MCP server. Enter a name, choose stdio, HTTP or SSE, and select the installed agents that should receive it. For stdio, enter the executable separately and put one argument on each line; spaces within a line stay in that argument. Add environment variables or HTTP headers as name/value pairs. Add skills selects an existing folder containing skill folders, each with SKILL.md. Choose the parent skill-set folder, then the agents. Preview shows links or adapter settings before Apply. Original files stay in place; links follow later edits, and skills can include scripts agents may run. Native folders already read automatically need no new link. Discovery checks at most 200 entries per directory, one category level deep, with 1,000 entries in total; choose a smaller folder if needed. A preview supports up to 32 agents and 200 links. Undo removes added links or restores settings while preserving later changes. Online catalogs, downloading skills and MCP tool checks are not part of these local forms.

The app looks at start, in the background and without running anything, for programs on this PC that offer an MCP server (their files hold the protocol’s own words; how to start them comes from their own usage text) and for skill sets that apps brought along. Managing the risk

The risk level is the most serious point the card finds:

  • High risk — it can do serious things without asking: run any command, or work with no sandbox and no questions. Fine in a throwaway container or virtual machine; on your own PC, let it ask first.
  • Medium risk — some things happen without asking, such as editing files in the project, or an automatic review decides for you.
  • Low risk — it asks before anything that matters, or cannot do it at all.

Good habits, whatever the settings:

  • Ask first for commands on your own computer; allow single, harmless commands (such as git status) with an allow rule instead of allowing the whole shell.
  • Switch the sandbox on where the agent has one (Claude Code, Codex, Cursor CLI), and leave the network in it off unless a task needs it.
  • Start agents in the project folder, not in your home folder, and keep keys and passwords out of it.
  • Keep MCP servers few: only the ones you use and trust. Each runs with your rights.
  • Run unattended work (bypass mode, “YOLO”, Pi with all tools) in a container or virtual machine.
  • Local LLMs on 127.0.0.1: their servers have no password.

Caution An automatic review (Claude Code's auto mode, Copilot's assisted, Cursor's auto-review, Hermes's smart) is a second AI judging each step. It saves questions, but it is a judgement, not a wall.

The words explained

What a sandbox changes: commands reach only the project folder and what you allow.

Sandbox
A fenced-off area the agent's commands run in. Inside it a command can touch only the project folder (and what you allow) — not the rest of your home folder, your SSH keys or browser data, and often not the internet. Without one, a command the agent runs can do anything you can.
Approval (asking first)
Before the agent edits a file or runs a command, it shows what it wants to do and waits for Yes or No. The less it may do without asking, the more control you keep, and the more often you are asked.
Allow and deny rules
Lists of commands or tools the agent may use without asking (allow) or never (deny). Deny wins over allow. A rule that allows every shell command switches approval off for the shell.
Trusted folder
A folder you said the agent may work in. There it also uses the folder's own instructions and settings, which can come from someone else when you clone a project.
Network access
Whether commands may reach the internet. Code that reads your files and can send data out could leak them; installing packages needs the network too.
Bypass (“YOLO”)
Everything without asking and without limits. Only for a throwaway virtual machine or container.
Automatic review
A second AI model lets harmless actions through and asks about the rest.
Prompt injection
Instructions hidden in a web page, file or tool answer that try to make the agent do something you did not ask for. Asking first, a sandbox and no network stop it.
Secret redaction
Text that looks like a password, token or key is masked before the model sees it or it reaches a log.
Tools
What the agent can do at all: read, write, run commands, search the web. A tool it does not have cannot be misused.
MCP server
A small program that gives the agent extra tools. It runs as you, with your rights.
127.0.0.1 (localhost)
An address only programs on this PC can reach. A server on 0.0.0.0 can be reached from every device on your network.

Privacy and safety

  • No administrator rights for the app. It never runs as root and never sees a password. Installing an agent that comes as a system package (such as Hermes or OpenClaw) runs the system's package manager through sudo in a terminal you watch, after showing you the command.
  • No credentials read. It reads the agents' settings, but never their credential files. Whether an agent is signed in is judged from whether such a file exists. Values of keys and headers are never shown.
  • No conversations read. Usage figures are read as numbers and times only. The one exception is watching an instance In the background (Terminals…), on your click, for that instance only; nothing of it is stored.
  • Network only when asked — searching models, MCP servers or skills, installing, testing a server — plus an update check every few hours.
  • Checked downloads. Programs are installed only when the download matches the checksum its release publishes.
  • Previews and Undo. Every change to another program's settings is previewed, backed up and can be undone. Settings that may hold keys are written readable only by you.
  • Bounded. Every program runs without a shell, and every answer is read with a size and time limit.
  • AI features only when you choose them. Smart Check's look-ups run on a click, the daily AI checks only when switched on. The agent gets a short summary (names, versions, models), never keys or settings values, handed over in a way other users of the computer cannot read; its answers are checked before they are shown and never run. Tasks run in a terminal you watch, and the agent asks before each step. You use them at your own risk.

The README in each repository lists in full what is read, started and written.

Glossary

Approval
An agent asking before it changes a file or runs a command (see The words explained).
Context
How many tokens of text a model can keep in mind at once.
GGUF
The file format for models used by llama.cpp, LM Studio, Ollama and KoboldCpp.
Prompt injection
Hidden instructions in a page, file or tool answer that try to steer an agent.
Quantization
Storing a model with fewer bits per weight (for example Q4_K_M, about 4.8 bits) so it is smaller, with a small loss of quality.
Mixture of experts
A model where only part of the parameters work for each token (35B-A3B: 35 billion in all, 3 billion active), which makes it fast for its size.
Sandbox
A fenced-off area an agent's commands run in, reaching only the project folder and what you allow.
Token
A piece of text, roughly three quarters of a word, that models read and write.
User service
A background program started by systemd for your user only, without administrator rights.
